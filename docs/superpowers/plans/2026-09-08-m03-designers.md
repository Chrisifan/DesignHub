# M03 设计师管理 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成可编辑草稿、不可变发布档案、默认/归档与授权作品集创建流程。

**Architecture:** 设计师库保存可复用档案，项目保存具体版本快照。作品集 UI 先开发本地选择与审核，视觉分析通过 M06 能力接口接入。

**Tech Stack:** React、M02 存储；G08 视觉分析与 G09 压缩包能力候选；准确依赖版本在研究采用记录中锁定。

**Spec:** [首版架构](../specs/2026-09-08-designhub-v1-design.md)，[UI 说明书](../../product/APPLICATION-GUIDE-FOR-UI.md)，[主计划](2026-09-08-designhub-v1.md)。

## Global Constraints

- Electron renderer 负责设计师编辑交互；保存走 M02 的受控存储，作品集解析及带凭据分析走 M06 后端。导入的作品集页面不作为有 Node 权限的窗口运行。

- 先调研成熟框架或第三方库，再写对应功能实现；未核验候选不等于选型。
- 按模块先写测试用例和 checklist，再实现并对照验证；改到已验证模块必须记录影响并回归。
- 所有自写函数遵守用户“箭头函数”要求；不能默许原生代码例外。
- 核心浏览、编辑、历史、检索、导出、备份离线可用；云请求不在重连后静默提交。
- 无平台账户；提供方密钥只存系统安全存储，不进项目、包、备份、日志。
- 主计划的其余全局约束和模块记录协议全部适用。先创建 `docs/verification/M03.md`，再实现下列目标文件。
- 下列代码是计划中的行为测试及核心规则片段；完整用例还必须覆盖每项验收场景，不以片段替代模块交付。

export const resolveDesigner = (input: {
  project?: string; workspace?: string; global?: string;
  available: string[]; builtin: string;
}) => [input.project, input.workspace, input.global]
  .find((id): id is string => Boolean(id && input.available.includes(id)))
  ?? input.builtin;

- [ ] **Step 3：实现最小完整用例。**

```ts
export const selectPortfolioSources = (
  sources: { id: string; selected: boolean }[], rightsConfirmed: boolean,
) => {
  if (!rightsConfirmed) throw new Error('RIGHTS_REQUIRED');
  return sources.filter((source) => source.selected).map((source) => source.id);
};
```
