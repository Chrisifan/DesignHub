# M02 本地工作区 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现可移动、单写者、可恢复的工作区及项目存储能力。

**Architecture:** Electron main process 负责真实文件和安全路径；项目元数据由同一受控 SQLite 连接/事务所有者管理，renderer 只能调用 typed bridge。先落实原子创建与只读，再加备份恢复，避免无测试的数据库通用封装。

**Tech Stack:** G04/G09：SQLite、文件 API 和归档库候选；准确依赖版本在研究采用记录中锁定。

**Spec:** [首版架构](../specs/2026-09-08-designhub-v1-design.md)，[UI 说明书](../../product/APPLICATION-GUIDE-FOR-UI.md)，[主计划](2026-09-08-designhub-v1.md)。

## Global Constraints

- 先调研成熟框架或第三方库，再写对应功能实现；未核验候选不等于选型。
- 按模块先写测试用例和 checklist，再实现并对照验证；改到已验证模块必须记录影响并回归。
- 所有自写函数遵守用户“箭头函数”要求；不能默许原生代码例外。
- 核心浏览、编辑、历史、检索、导出、备份离线可用；云请求不在重连后静默提交。
- 无平台账户；提供方密钥只存系统安全存储，不进项目、包、备份、日志。
- 主计划的其余全局约束和模块记录协议全部适用。先创建 `docs/verification/M02.md`，再实现下列目标文件。
- 下列代码是计划中的行为测试及核心规则片段；完整用例还必须覆盖每项验收场景，不以片段替代模块交付。

```ts
};
```

**Interfaces:** `canMigrate: (input: {backupVerified:boolean; writable:boolean; from:number; to:number}) => boolean`；备份产物必须校验 DB 一致性和内容闭包，恢复默认新目录。

```tsx
  expect(canMigrate({ backupVerified: false, writable: true, from: 1, to: 2 })).toBe(false);
  expect(canMigrate({ backupVerified: true, writable: true, from: 2, to: 1 })).toBe(false);

```

- [ ] **Step 2：运行失败测试。**

Run: `pnpm test:unit -- src/features/workspace/migration-policy.test.ts`
Expected: 目标行为尚未实现导致失败；若首先因依赖/导入缺失失败，补齐最小导出后确认行为 Red，不能将环境错误当验证结果。

- [ ] **Step 3：实现最小完整用例。**

```ts
export const canMigrate = (input: {
  backupVerified: boolean; writable: boolean; from: number; to: number;
}) => input.backupVerified && input.writable && input.from < input.to;
```

用 SQLite 一致性备份能力，而非运行中只复制 DB 主文件；增量素材按清单校验写入，最后发布完整备份标记。定期备份仅在应用运行且目的盘可用时执行，退出时不承诺独立守护进程；下次启动显示错过周期可补做。恢复到新位置，核对清单后打开。迁移先备份验证，再事务升级；中断回滚。
