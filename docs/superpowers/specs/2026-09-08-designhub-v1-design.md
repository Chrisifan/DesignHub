# DesignHub 首版架构与功能基线

创建：2026-09-08；更新：2026-09-09。状态：Q1–Q66 已确认并冻结为 V1 实施基线。依据：开发守则、ADR 0001–0024、[UI 基础规范](../../product/UI-FOUNDATIONS.md)，以及用户批准的“基础契约优先、按可交付能力推进”与切换 Electron 的决定。

这是供实施计划引用的技术设计。业务完整说明见 [UI 应用说明书](../../product/APPLICATION-GUIDE-FOR-UI.md)，视觉、窗口和交互约束见 [UI 基础规范](../../product/UI-FOUNDATIONS.md)。Electron 已选并完成部分官方资料核验；具体接口/目录仍为待实施计划，Electron 平台实验与正式应用均未实现。

## 1. 全局约束

- 首版正式支持 macOS 与 Windows；Linux、完整移动编辑器和多人并发写入不在首版。
- 用户数据本地保存；工作区自包含；项目独立保存元数据，项目包携带所需依赖。
- 先调研成熟框架或第三方库，再写对应功能实现；未核验候选不等于选型。
- 按模块先写测试用例和 checklist，再实现并对照验证；改到已验证模块必须记录影响并回归。
- 严格按照功能计划，不增加预期之外的插件系统、微服务、事件总线、同步协议或泛化工作流引擎。
- 所有自写函数遵守用户“箭头函数”要求；不能默许原生代码例外。
- 核心浏览、编辑、历史、检索、导出、备份离线可用；云请求不在重连后静默提交。
- 无平台账户；提供方密钥只存系统安全存储，不进项目、包、备份、日志。
- 对话、图像生成与编辑能力可分别配置；不自动切换模型或提供方。
- 首版简体中文与英文；非画布流程键盘、焦点和读屏可用。
- UI 只参考 Figma 中经 UI 基础规范列入允许表的 11 个 P 开头深色 DesignHub Frame；同文件的其他 Software Buddy 页面不进入实现。
- 暗色与明亮主题共用组件树、字体、间距、断点和交互；中文文字按钮动作短语不超过 4 个汉字，按钮与标签不得异常换行。
- M01 可依据已确认的 UI 基础规范实现窗口外壳；其余模块的视觉实现须先取得 UI 设计师对相关页面、状态、双语和响应式行为的交付或明确确认，领域逻辑与技术验证可以先行。
- 首版诊断只生成可预览、由用户主动导出的本地诊断包，不实现自动网络发送或遥测接收端。

## 2. 八个模块与真实开发顺序

| 模块 | 对外负责 | 不负责 |
| --- | --- | --- |
| M01 基础与验证 | 选型证据、宿主边界、工程、测试、通用 UI 状态 | 全部未来平台的泛化兼容层 |
| M02 本地工作区 | 目录、项目存储原语、锁、格式、废纸篓、备份 | 对话、画布具体语义 |
| M03 设计师 | 草稿、发布、默认、归档、作品集审核与分析入口 | 项目历史的改写 |
| M04 项目与素材 | 两种创建入口、简报、文档、品牌、素材、版本、贡献、时间线 | 模型供应商协议 |
| M05 组合画布 | 编辑会话、图层、文字、遮罩、选区、视口与提交 | 模型任务调度、专业矢量编辑 |
| M06 Agent 与提供方 | 凭据、能力、上下文、工具调用、任务、记录、恢复 | 任意脚本执行、后台偷偷上传 |
| M07 图像工具与交付 | 工具目标、参数、结果落版、图像/PDF/包导出 | 复制一套独立历史或任务系统 |
| M08 检索与发布 | 索引、设置、端到端、离线、平台打包及发布验收 | 新业务功能扩张 |

依赖顺序为 M01 → M02 → M03/M04 的离线部分 → M05 → M06 → M03/M04 的模型闭环 → M07 → M08。M02 的备份/迁移接口先完成，完整内容校验在 M04 接入后补验。M08 的发布要求从 M01 开始验证，不到最后才发现桌面自动化不可行。

M03 的作品集分析、M04 的对话简报依赖 M06。这两个模块先以有标识的测试替身验 UI 和契约，M06 接入真提供方后才可称模块完整验收，不能将替身冒充已交付 AI 能力。

## 3. 工程组织建议

采用单应用仓库；不为未来手机端预建 monorepo、共享包发布或服务集群。Electron 主进程、预加载桥接和 renderer 是同一桌面应用的三个明确边界，以下路径是计划创建的目标，目前均非现有实现。

```text
src/
  app/                     入口、路由、中文/英文、错误边界
  platform/                renderer 侧唯一桌面桥接入口与类型
  desktop/                 Electron main/preload、窗口、文件、系统凭据适配与 IPC
  features/
    workspace/             工作区与备份界面及用例
    designers/             档案与作品集
    projects/              简报、项目与文档管理
    assets/                导入与受管资源
    brands/                品牌包与快照
    revisions/             修订、贡献、时间线
    canvas/                文档编辑与视口
    providers/             固定内置适配器与能力
    agent/                 上下文与受限工具编排
    tasks/                 持久任务生命周期
    image-tools/           图像工具目标及参数
    delivery/              导出与包
    library/               本地索引与筛选
    settings/              本机与工作区设置
  shared/                  已有两个以上消费者的少量基础类型和 UI 元件
tests/
  fixtures/                自有/许可明确的图像、字体与项目样本
  integration/             真实文件、数据库、进程恢复
  e2e/                     浏览器交互及原生宿主冒烟分开
docs/
  product/                 UI / 功能说明书
  research/                调研与技术采用门槛
  verification/            测试、checklist、回归证据
  superpowers/plans/       全模块任务计划
```

Electron 安全边界：显式使用 `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`；preload 通过 `contextBridge` 暴露具体操作。main 校验调用窗口/主 frame/origin、参数和项目访问范围后执行文件、SQLite、对话框及凭据操作。CSP 与导航限制只允许已打包应用代码；作品集页面由后端解析数据，不加载成特权应用页面。原始 `ipcRenderer`、Node `require`、shell/eval 不进入 renderer。

主窗口采用无可见系统标题栏但保留原生窗口控制的方案。macOS 的 vibrancy、Windows 的 Mica/Acrylic `backgroundMaterial` 和实色降级分别实现并验证；不以 Electron `transparent: true` 作为主窗口默认，因为官方明确记录了调整尺寸与 Windows 最大化限制。自定义窗口栏划分 drag/no-drag 区域，交通灯或 Window Controls Overlay 有独立安全区。

`src/desktop/main.ts` 管生命周期，`preload.ts` 只桥接，`src/platform/contracts.ts` 定义可序列化输入输出。后端具体实现按需放 `src/desktop/storage/`、`security/`、`workers/`；只在对应模块落地时创建。CPU 密集图像任务交给 Worker/UtilityProcess，main 保持可响应；数据库连接和事务只由一个执行上下文持有，不能跨 IPC 或线程拆分事务。平台 facade 不引入同时支持 Tauri/Electron 的适配框架。

每个 feature 内按需要建 `model.ts`、用例文件、组件和就近测试；不为每个功能机械建立 controllers/services/repositories 三层。组件不直接访问文件系统或凭据。外部库的对象实例不得进入持久项目格式；画布保留应用自己的有限图层结构。

Renderer 的推荐 UI 基线为 shadcn/ui 的 Radix 版本、Radix UI Primitives、Tailwind CSS 与 Lucide React；它们仍须在 M01 锁定准确版本、许可证、Chromium 兼容和包体积后才能记为采用。shadcn 生成到仓库的组件属于项目源码，函数与 React 组件同样使用箭头函数。默认以 CSS 完成短动效，不预装通用动画框架。主题只通过语义 token 和原生材质切换，不建立两套页面实现。

## 4. 本地所有权与可携带性

本机配置只保存偏好、本机操作者档案、最近工作区位置、全局默认引用和模型连接非机密描述。系统安全存储持有凭据。工作区中保存品牌、设计师库、共享素材、项目文件夹与废纸篓；索引可以重建，工作区身份与设置不能只存进可丢弃索引。

项目包含独立元数据、必要设计师/品牌快照、内容清单、修订版及可预览产物。建议 SQLite 为项目数据库候选，采用与版本先过调研门槛。工作区共享素材与项目的引用用内容标识，禁止把某设备绝对路径当成唯一来源。

“工作区可移动”和“项目包可独立交接”分开验证：工作区整体移动后所有内部引用仍成立；导出单项目包时遍历引用闭包，补齐所有所需受管素材与快照。直接从磁盘抽走项目子目录若有共享依赖，应用必须检测缺失；产品提供“导出独立项目包”作为保证完整的交接入口。

实现优先用内容清单加复制确保正确，再在同工作区内采用已验证去重。不可通过隐藏跨工作区目录节省空间。硬链接等优化只有在移动、删除、备份验证通过后采用，不能因优化改变不可变资源。

全局默认设计师可能指向当前未打开的工作区；新项目要取得具体快照才能使用，无法取得时明确回退内置通用档案。库中的归档与项目快照是不同对象，不做跨目录级联删除。

## 5. 关键领域实体与不变量

| 实体 | 必需关联 / 属性 | 不变量 |
| --- | --- | --- |
| Workspace | 稳定 ID、格式版本、目录句柄、设置 | 单写者；路径可变，身份不变 |
| Project | ID、简报快照、文档、资源清单 | 确认创建后才成为正式项目 |
| CreationDraft | 临时简报、创建对话、附件 | 不计为项目；可放弃；收费请求仍有记录 |
| DesignDocument | ID、尺寸、关联来源、分支与定稿指向 | 定稿指向明确修订版，不指向“最新” |
| Revision | ID、父版本、场景快照、资源、操作记录 | 完成后不可修改；父版本不得跨错文档 |
| Contribution | 修订版、设计师版本、角色、来源操作 | 不靠当前设计师字段推断历史贡献 |
| OperatorAttribution | 修订版或操作、本机操作者标识、显示名称快照 | 不授予权限；跨设备保留旧快照，新操作使用当前设备档案 |
| DesignerVersion | 稳定档案 ID、版本 ID、规则、来源 | 发布产生新版本；草稿可编辑 |
| BrandSnapshot | 项目快照与覆盖字段 | 品牌库修改不影响过去结果 |
| Asset | 内容标识、文件类型、尺寸、来源、保管方式 | 历史仍引用的内容不可清空 |
| ModelTask | 来源、能力、基版本、设计师、提供方、尝试、状态 | 已完成结果只能落版一次；不能自动付费重试 |
| ExportRecord | 来源修订版、参数、产物校验、位置 | 写入失败不能标成功；外部移动不删除记录 |

项目前和设计师草稿也可能运行文本/视觉分析任务：任务来源使用项目、创建草稿或设计师草稿三选一；进入正式项目时复制或关联可见创建记录。全局任务列表只聚合明确来源，不建立云端账号历史。

## 6. 原子操作与历史

项目创建：校验简报和可写目录 → 生成临时项目目录 → 写数据库和初始快照 → 完整校验 → 原子发布目录 → 更新可重建索引。重试携带同一操作标识，防重复项目。失败保留原草稿，清理仅属于本次的临时内容。

模型结果：将产物写入临时内容区并验证 → 登记资源 → 数据库事务插入修订版、贡献、任务完成事件 → 发布结果引用。出现崩溃时按操作标识核对，不能重复插入版本或留下指向缺失文件的完成状态。

手工编辑以一次手势/提交为批次，定时保存编辑草稿保护未提交工作。业务修订与运行日志分开，不把每帧拖拽记录成新版本。不采用通用事件溯源框架；简单的快照和追加操作记录足以表达当前需求。

任务绑定基版本 r1，用户期间编辑出 r2 时，迟到的模型结果 r3 仍从 r1 分支，不改写 r2 或定稿。取消后迟到结果不能冒充正常完成；保存诊断或可找回结果的具体行为由任务详情明确说明。

### 6.1 跨模块接口契约

以下为计划落地的最小业务接口，类型放在拥有它的 feature 内并通过其入口导出。签名在执行时与测试一起实现；不增加一个通用插件 SDK。场景内容先经 M05 schema 校验，再作为不可变内容由 sceneAssetId 引用，避免 M04 耦合画布库实例。

```ts
// src/features/revisions/commit-revision.ts
export type CommitRevisionInput = {
  projectId: string;
  documentId: string;
  baseRevisionId: string | null;
  operationId: string;
  sceneAssetId: string;
  assetIds: string[];
  contributions: {
    designerVersionId: string;
    role: 'lead' | 'direction' | 'revision';
  }[];
};
export type CommitRevision = (input: CommitRevisionInput) => Promise<{ revisionId: string }>;
export type SetFinalRevision = (documentId: string, revisionId: string) => Promise<void>;

// src/features/agent/analyze-portfolio.ts
export type AnalyzePortfolio = (input: {
  sourceIds: string[]; designerDraftId: string; connectionId: string;
}) => Promise<{ taskId: string; designerDraftId: string }>;

// src/features/agent/draft-brief.ts
export type DraftBrief = (input: {
  text: string; creationDraftId: string; connectionId: string;
}) => Promise<{ taskId: string; creationDraftId: string }>;
```

分析和简报函数返回任务及草稿标识；生成内容经任务完成后写入对应草稿，由 UI 订阅读取，不把长模型调用伪装成同步立即返回。实际函数分别命名 commitRevision、setFinalRevision、analyzePortfolio、draftBrief，使用箭头函数实现上述类型。

## 7. Agent 与数据范围

提供方接口区分对话、视觉分析、图像生成、图像编辑及具体图像工具能力。用户只配置经验证的内置适配器。凭据由 main 中经 G07 验证的系统凭据适配器使用，前端通常只拿连接标识。用户输入 Key 的表单将其发送给 main 后清空，不写日志或持久化；已存 Key 不读回 UI。safeStorage 的应用密文存储不自动等于 ADR 0015 要求的系统凭据存储。

构建上下文时列出当前项目简报、当前文档、明确选择的素材/对话记录、品牌和设计师快照。统一时间线允许项目内交接摘要；其他项目内容需用户显式附加。作品集网页、图像内容和模型文本都是输入资料，不能升级成读取全磁盘或任意网络权限的指令。

编排只调用固定工具白名单并验证参数、目标 ID、区域和支持能力。涉及新提供方或首次原图上传时通过产品已确认的告知流程；已同意的同一范围不加重复弹窗。成本未知保持未知，不自动模型替代。

恢复时优先查远端 request ID；缺少幂等/查询支持则标记结果未知，等待用户重试。取消语义以提供方真实能力为准；关闭应用不承诺远端计算停止。

## 8. 画布、图像与格式边界

场景格式限于栅格、文字、基础形状、变换、可见性、层序、裁切和遮罩。持久数据通过 schema 校验；UI 渲染器独立于场景格式。图像计算不占用交互线程，大图通过缩略图/分级预览降低内存压力，不先自研 GPU 编辑器。

文本必须验证中文输入法、系统字体、缺字检测与导出外观。选择 Konva/Fabric 等候选前验证文字覆盖层编辑、遮罩、裁切、序列化和大图导出。不能仅凭示例能拖动矩形就选型。

SVG 导入不执行脚本/外部资源；PDF / PSD 仅扁平化，需验证所选解码链路和许可证。PDF 多页通过用户页选择生成独立素材；不能默把整本导入为不明尺寸图像。HEIC 和 PSD 在两平台均有真实样本验证，失败不宣称支持。

PNG/JPEG/WebP 为 sRGB；普通 PDF 可以保留栅格外观，文字不默认嵌字体。交付包只带选中输出和清单，不包含完整内部会话。署名优先格式支持的元数据，不支持时用随附清单；明确平台可能移除元数据。

## 9. 发布与质量策略

每个模块以单元测试、真实本地集成、交互测试和人工 checklist 组合验证；模型替身验证故障和幂等，真实提供方用授权素材做少量带费用上限的验收。浏览器 E2E 通过不能替代原生系统文件选择、凭据、窗口、签名安装测试。

Electron 的选择、基准样本、测试能力和安全边界见 [ADR 0024](../../adr/0024-electron-react-desktop-runtime.md) 与 [研究门槛](../../research/DEPENDENCY-GATES.md)。不能将普通浏览器 Playwright 用例等同于 Electron 桌面宿主自动化。

正式双平台发布要求双平台证据；缺少 Windows 设备/runner 或签名凭据时登记该项未验证，继续其他模块，禁止把仅 macOS 的结果写成双平台通过。尚无预算/人员排期，不提供虚构精确上线日期，使用依赖和验收里程碑推进。

## 10. 已识别的验证前提

1. Electron 是当前桌面基础框架；具体 Electron、打包器和原生模块版本在 M01 实施前锁定。
2. Electron 主进程、预加载和工具进程均使用 JS/TS，继续遵守所有自写函数采用箭头函数；第三方原生模块按 ABI 和许可证核验，不把其内部实现当作本项目代码。
3. 未知的未来项目 schema 无法保证完全可解析；只读兼容至少能展示已知清单或独立预览，无法解析时显示能力限制，不盲开新数据库并写入。
4. 默认不归档作品集原图与可复现记录并不冲突：保留来源和特征记录，但不能承诺未保留图片仍可再次重放分析。
5. 数值性能门槛是待基准校准的工程验收目标，不是已经测得性能或额外市场承诺。
6. Figma 与官方文档只证明存在设计和技术路径；无标题栏、透明材质、窗口调整、中英文不换行、减少动态和两平台表现必须在真实 Electron 窗口重新验证。

## 11. 计划覆盖

完整范围由[主计划](../plans/2026-09-08-designhub-v1.md)的 Q1–Q66 追踪表覆盖。执行时以[开发守则](../../DEVELOPMENT-GUARDRAILS.md)及[验证登记](../../verification/MODULE-REGISTER.md)为门槛。冻结后新增或修改产品能力必须先记录为基线变更，指出受影响模块和重新验证证据；依赖版本及工程实验仍按既有门槛决策，不视为重新打开产品范围。
