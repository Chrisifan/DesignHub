# DesignHub 图像工具与创作工作流设计

日期：2026-09-20
状态：已确认
确认范围：Q1–Q25

## 1. 目的

本设计在当前 DesignHub 产品模型上安置六类能力：批量抠图、画面延展与主体补全、去除水印、智能编排、样机效果图和更换背景。目标不是增加一组孤立按钮，而是明确它们分别属于文件处理、画布编辑还是项目创作，并让任务、结果、失败恢复和历史归属保持一致。

本设计是产品与系统边界说明，不是实施计划。具体文件拆分、接口签名和任务顺序将在后续 implementation plan 中确定。

## 2. 当前状态与差距

当前产品已经是本地优先的项目型平面设计工作 Agent。核心层级为工作区、设计项目、设计文档、不可变修订版、候选变体和定稿。现有 P14 工具检查器位于画布工作台内，P15 模型任务提供聚合运行视角。

### 2.1 已有计划或代码骨架

- `remove-background`、`replace-background`、`remove-object`、`inpaint`、`expand`、`smart-crop`、`upscale` 和 `resize` 已存在于图像工具 allowlist。
- 画布已有工具检查器、区域输入、模型任务、候选、修订版和素材管理的基础结构。
- 产品说明已经规划去除背景、更换背景、对象移除、局部重绘、画面扩展、智能裁切、放大和尺寸转换。
- 项目对话与设计生成已经具备“附件 / 参考 → 模型任务 → 候选 → 继续编辑 / 定稿”的基础链路。

### 2.2 尚未闭环的基础能力

- 当前工具调用并未可靠绑定用户选中的图片图层，而是可能使用文档中的第一张受管图片。
- 当前遮罩主要是矩形区域输入，不是可持久化、可恢复的真实像素遮罩。
- 当前提供方只声明粗粒度 `image-editing` 或 `image-generation` 能力，不能证明某个具体工具、模式、遮罩或透明输出真实可用。
- 当前模型请求可以无界并发，没有跨作业的受控调度、限流或公平性。
- 当前任务是单任务结构，没有父作业、处理项、相对来源路径或输出目录契约。
- 素材导入和存储会丢失来源目录结构；文件夹选择和目录树输出不存在。
- 当前部分导出路径仍未完成真实图片图层的完整合成，不能作为新增图像能力的交付基础。
- 现有测试主要证明请求序列化和状态契约，不证明真实模型语义、保护区域像素不变或人工画质。

### 2.3 本次新增或扩展的范围

| 能力 | 当前归类 | 本设计变化 |
| --- | --- | --- |
| 去除背景 | 已规划、已有单图画布骨架 | 新增独立单图 / 文件夹作业；画布入口继续保留 |
| 更换背景 | 已规划、已有画布骨架 | 背景来源扩为生成图片、用户图片和纯色，共享主体保护 |
| 画面扩展 | 已规划、已有泛化 `expand` | 拆为原景延展、氛围延展；主体补全成为独立局部工具 |
| 去除水印 | 全新 | 作为画布“修复与移除”中的受约束预设 |
| 智能编排 | 底层能力部分存在 | 产品化为结构化设计文档生成工作流 |
| 样机效果图 | 全新 | 引入内置样机模板与受控合成工作流 |

## 3. 核心产品决策

### 3.1 双轨产品边界

DesignHub 同时提供两种工作模型：

1. **项目创作**：需要画布、选区、构图、候选比较、继续编辑或项目历史的操作，结果属于设计文档及其修订版。
2. **独立文件处理**：用户只需要处理本地单图或文件夹并取得文件结果时，不要求创建设计项目。

双轨边界见 [ADR 0025](../../adr/0025-project-and-standalone-image-workflows.md)。独立处理仍属于当前工作区的本地历史，但不属于任何设计项目、设计文档或修订版。

### 3.2 入口分配原则

- 用户想继续创作时，能力进入项目或画布。
- 用户只想取得文件结果时，能力进入一级“图像工具”。
- 去除背景等少数底层能力允许双入口；两个入口共享执行能力，但生成不同的业务结果。
- 不为六类功能建立第二套模型连接、任务状态或素材实现。

## 4. 信息架构

### 4.1 一级“图像工具”

主导航在“素材库”附近新增一级“图像工具”。页面包含：

- 工具目录：首批提供去除背景、放大、尺寸转换和格式转换。
- 新建作业入口。
- 活跃与最近作业列表。
- 当前作业的逐图结果网格。
- 选中处理项的原图 / 结果对比、错误、重试与文件操作抽屉。
- 指向全局模型任务记录的链接。

页面采用“左侧作业列表 + 右侧当前作业结果网格”的主从结构。多作业同时运行时，用户可稳定切换；逐图结果会随完成状态填入网格。旧作业按时间归档，不使用临时标签页长期堆积。

### 4.2 项目与画布入口

- 项目概览的“新建设计”增加“智能编排”和“样机效果图”。
- 已有设计文档的画布工作台提供“智能编排 / 重新编排”。
- 素材详情对适合的 Logo、符号或 IP 资产提供“制作样机”。
- 画布工具继续位于当前工作台工具检查器内，并按“背景”“构图”“修复与移除”“增强与转换”分组。

### 4.3 与“模型任务”的关系

- “图像工具”拥有作业、逐图结果和业务操作。
- “模型任务”继续聚合项目生成、作品集分析、画布编辑和独立处理项的底层模型调用。
- 模型任务可以定位回所属作业、项目或草稿。
- 状态只持久化一份；两个页面不会各自维护可分叉的任务副本。

## 5. 独立图像处理作业

### 5.1 作业边界

一个独立图像处理作业只包含：

- 一种图像处理工具；
- 一套固定参数；
- 一张图片或一个文件夹来源；
- 一个用户选择的输出位置；
- 一个自动建议且可编辑的作业结果文件夹名；
- 多个逐图处理项。

首版不支持在同一作业中编排“抠图 → 放大 → 格式转换”等多步骤流水线。用户可以从一次作业的结果创建下一次作业；只有真实高频需求出现后才考虑保存流水线配方。

### 5.2 来源与路径

- 单图和文件夹使用原生文件 / 目录选择器。
- 扫描阶段生成来源清单，记录每张图相对来源根的安全路径。
- 目录遍历默认不跟随符号链接；不可读文件、循环链接、不支持格式和路径冲突逐项报告。
- 相对路径必须经过跨平台规范化，拒绝绝对路径、父目录跳转、控制字符和保留设备名。
- 扫描完成后先展示可处理数量、拒绝数量和预计输出结构，再允许执行。

### 5.3 输出契约

用户选择输出位置后，应用在其下创建独立作业目录，例如：

```text
用户选择的输出位置/
  商品图抠图-20260920-1430/
    鞋类/
      正面/
        a.png
```

- 文件夹来源完整保留相对目录结构。
- 原文件永不覆盖。
- 每次重跑创建新的作业目录，不提供覆盖旧结果的默认路径。
- 去除背景结果使用支持透明度的格式；无法提供有效透明结果时，该项失败，不能静默改为有底色图片。
- 结果先写入作业内临时路径，完成格式、尺寸和透明度校验后再原子发布。
- 只有文件发布成功后，处理项才可标记完成。
- 用户可对完成结果执行“打开文件”“在文件夹中显示”“打开结果文件夹”和“明确导入素材库”。

### 5.4 父作业与图像处理项

父作业负责来源清单、工具参数、输出目录、聚合进度和批量操作。每个图像处理项对应一张来源图像，持有自己的状态、尝试记录、结果和错误。

处理项显示状态：

- 排队；
- 处理中；
- 完成；
- 失败；
- 已取消；
- 结果未知。

“结果未知”用于应用中断后无法从提供方确认远端结果的情况，不会自动重新提交收费请求。

父作业根据处理项聚合为：等待、运行中、已暂停、已完成、完成但有失败项或已取消。部分失败不回滚已成功文件。

### 5.5 调度

- 所有独立作业和项目模型任务共享按提供方 / 连接限制的受控调度器。
- 普通用户不设置线程数或请求并发数。
- 同一作业内按稳定顺序调度；多个活跃作业之间轮转取项，避免一个大文件夹长期饿死其他工作。
- 提供方给出限流或 `retry-after` 时，调度器暂停对应连接的新请求并向用户展示原因；不会静默换模型。
- “暂停作业”只停止安排新处理项；已运行请求继续或按提供方能力请求取消。

## 6. 画布图像工具

### 6.1 统一目标与结果契约

- 工具默认作用于当前选中的图片图层。
- 检查器始终显示目标缩略图、图层名和来源修订版。
- 没有选中有效图片时，工具不可执行，并解释如何选择目标。
- 文字、Logo、形状和其他图层不会被暗中扁平化进入模型输入。
- 需要处理整张合成画面时，用户必须显式创建合成副本。
- 每次执行记录允许生成区域、保护区域、模型、参数和基础修订版。
- 模型完成后先产生候选结果；用户可以比较、继续编辑或保留为候选，不能自动覆盖当前画布。
- 当用户在任务期间继续编辑时，迟到结果仍从任务提交时的基础修订版分支。

### 6.2 去除背景

- 继续作为画布工具存在，并与独立图像工具复用底层能力。
- 画布结果成为候选修订版；独立入口结果成为文件。
- 支持在模型真实具备能力时调整边缘保留或修正主体遮罩。

### 6.3 更换背景

更换背景保持单一工具，并在检查器内选择背景来源：

1. 根据文字描述生成背景；
2. 使用用户选择的背景图片；
3. 使用纯色背景。

三种来源共享主体识别、可编辑遮罩、边缘处理、光照匹配和前后比较。主体是保护区域。用户背景图作为明确输入进入任务记录，丢失时不能用其他图片替代。

### 6.4 画面延展

“扩图”不再作为正式领域词。画面延展包含两个模式：

- **原景延展**：冻结全部原图像素，只生成画布新增区域，之后在本地合成。结果必须通过原图区域逐像素一致性检查。
- **氛围延展**：主体保护区域逐像素不变；原背景可以在明确可见的过渡区域内重新生成，以保证接缝自然。执行前显示主体保护区域和允许重绘范围。

两种模式共用目标尺寸、比例、延展方向和画布边界预览，但保真说明必须不同。

### 6.5 主体补全

主体补全是独立局部工具，而不是画面延展的第三种模式。用户通过笔刷、区域或可修正自动遮罩标记人物、物品或其他主体的缺失部分。选区外像素保持不变，结果作为候选修订版返回。

### 6.6 去除水印

- 位于“修复与移除”分组，作为可见的局部修复预设。
- 首次使用时要求用户确认拥有处理权；确认记录进入任务可见记录，但不对相同范围每次弹窗。
- 用户必须框选或涂抹水印区域，首版不提供自动全图检测或批量去水印。
- 选区外像素保持不变。

## 7. 智能编排

### 7.1 定位与入口

智能编排是项目创作工作流，不是独立图像工具。入口为：

- 项目概览：`新建设计 → 智能编排`；
- 画布工作台：`智能编排 / 重新编排`。

前者创建新的设计文档，后者基于当前文档创建候选分支。

### 7.2 输入角色

输入必须显式分为：

- **核心物料**：结果必须包含并保持独立可编辑图层，例如主商品、Logo、IP 和指定文案。
- **可选物料**：模型可以根据版面选择使用。
- **视觉参考**：只引导构图、色彩、材质或氛围，不要求复制其中的文字、Logo 或具体元素。

每项输入允许补充用途和约束，例如“主商品”“Logo 不可裁切”“仅参考留白”。流程还需确认交付尺寸、用途、文案、品牌快照、创作方向、禁用项和候选数量。

### 7.3 输出

- 输出必须是符合 DesignScene schema 的候选设计文档或候选修订版。
- 核心图片、Logo 和文字保持为独立图层；模型生成的装饰背景可以是栅格图层。
- 缺少任何核心物料、将指定文字烧进背景或仅返回扁平图片，都视为结构化生成失败。
- 候选支持比较、打开画布、继续编辑和定稿。

## 8. 样机效果图

### 8.1 定位与入口

样机效果图是“使用设计资产创建新的展示物料”，不是对当前图片做局部修改。入口为：

- Logo、符号或 IP 素材详情的“制作样机”；
- 项目概览的 `新建设计 → 样机效果图`。

结果保存为项目内设计文档。

### 8.2 模板范围

- 首版只支持应用内置、经过验证的样机模板，不支持用户创建模板。
- 模板包必须记录来源、许可证、版本、预览、支持的放置面、输入限制和跨平台渲染样本。
- 初始模板支持可控的放置面、透视、遮挡、裁切和有限颜色选项；复杂曲面、材质位移、多表面联动不进入首版。

### 8.3 保真与输出

- Logo、符号和 IP 资产不会被模型重新绘制。
- 用户可在模板允许范围内调整缩放、偏移和裁切。
- 源资产在设计文档中保持可替换引用，模板背景和效果层保持受控。
- 渲染需要验证几何、颜色、透明度、遮挡和清晰度，并进行人工视觉验收。

## 9. 提供方与能力模型

当前粗粒度 `image-editing` / `image-generation` 能力不足以支撑产品承诺。连接能力需要声明：

- 支持的具体工具与模式；
- 是否接受遮罩以及遮罩格式；
- 最大输入 / 输出尺寸和文件大小；
- 是否支持透明输出；
- 是否支持远端取消与请求状态查询；
- 是否返回费用、用量或请求标识；
- 可用模型及其参数范围。

工具检查器只显示所选连接真实支持的参数。能力不足时保留用户当前输入并引导连接设置；不自动选择替代模型。原景延展的像素冻结、样机模板渲染等本地合成能力不能由模型的模糊承诺代替。

## 10. 失败、恢复与安全

### 10.1 应用重启

- 已完成处理项保持完成。
- 未开始处理项进入暂停状态，等待用户继续。
- 运行中任务优先使用远端请求 ID 查询。
- 无法查询时显示“结果未知”，由用户决定是否重新提交。
- 不自动重复可能计费的请求。

### 10.2 取消

- 取消父作业会取消未开始处理项并停止继续调度。
- 正在运行的请求按提供方真实能力请求取消。
- 提供方不支持取消时，界面必须说明远端仍可能计算或计费。

### 10.3 文件与数据安全

- 输出使用显式选择的有限目录，不接受未验证的路径拼接。
- 临时文件和最终发布限制在作业结果目录内。
- 相对路径经过规范化并验证仍位于输出根下。
- 原图、遮罩和背景图片上传遵守现有首次数据外发确认；每次任务持续显示提供方和上传范围。
- 提供方凭据不进入作业记录、项目、输出目录或诊断包。

## 11. 验证策略

### 11.1 单元与属性测试

- 路径规范化、父目录跳转、Windows 保留名、大小写冲突和 Unicode 文件名。
- 父作业 / 处理项状态聚合、暂停、取消、失败重试和结果未知。
- 调度并发上限、跨作业公平性、限流暂停和无静默模型替代。
- 工具 / 模式能力匹配和参数裁剪。
- 原景延展原图区域逐像素一致。
- 氛围延展、主体补全和去除水印的保护区域逐像素一致。
- 智能编排场景中核心物料及文字图层完整。
- 样机资产几何、颜色和可替换引用保持。

### 11.2 文件系统集成测试

- 单图、深层目录、空目录、混合格式、部分不可读文件和符号链接。
- 输出目录结构、作业目录命名、临时写入、原子发布和磁盘满。
- 运行中退出、重启恢复、外接磁盘断开和输出目录被移动。
- Windows 与 macOS 的路径、文件名、原生选择器和打开目录行为。

### 11.3 UI 与端到端测试

- 一级“图像工具”导航、作业切换、进度、筛选、逐图详情和键盘操作。
- 画布选中图层与工具目标一致；无有效目标时不能执行。
- 保护区域可见、可编辑，并与实际上传遮罩一致。
- 模型任务可反向定位所属作业或项目。
- 智能编排与样机两个入口进入相同流程并产生设计文档。
- 双语、明暗主题、窄窗口、长路径和大批量结果下无关键操作被遮挡。

### 11.4 真实提供方与人工验收

协议测试不能替代真实质量。每个已支持工具 / 模式至少使用授权样本验证：

- 主体边缘、半透明、毛发和复杂背景抠图；
- 延展接缝、主体保护和大尺寸输出；
- 局部补全的解剖或物品连续性；
- 更换背景后的边缘、光照和接触关系；
- 样机遮挡、透视和跨平台渲染一致性；
- 智能编排的核心物料、文字准确性和可编辑性。

未经过真实模型与人工样本验收的能力只能标记为实验或不可用，不能仅凭适配器返回成功宣称交付。

## 12. 分阶段交付

### 阶段 0：共同基础

- 完成真实图片图层渲染、合成与导出。
- 将画布工具目标改为选中图层。
- 实现可持久化真实遮罩、保护区域和本地像素合成。
- 建立逐工具 / 模式能力矩阵。
- 建立共享受控调度器、任务持久化和恢复行为。
- 使用真实提供方与授权样本完成基础门禁。

### 阶段 1：独立文件处理

- 新增一级“图像工具”。
- 实现来源清单、目录扫描、父作业、逐图处理项和结果中心。
- 交付单图 / 文件夹批量抠图和安全目录树输出。
- 支持暂停、取消、失败重试、重启恢复、打开结果和明确导入素材库。

### 阶段 2：可靠画布工具

- 完成三种来源的更换背景。
- 交付原景延展、氛围延展和主体补全。
- 增加去除水印预设和首次权利确认。
- 完成候选比较、修订分支和保护区域质量门禁。

### 阶段 3：创作工作流

- 智能编排作为独立里程碑：输入角色、结构化场景生成、候选设计文档。
- 样机效果图作为独立里程碑：内置模板包、受控放置、渲染与授权验证。
- 两者接入项目时间线、素材动作、定稿与交付。

## 13. 非目标

- 不重新打开已冻结 V1，将所有新能力强塞入首版发布门禁。
- 不建立通用多步骤图像工作流编排器。
- 不提供自动全图或文件夹批量去水印。
- 不让用户设置底层线程数或直接控制模型并发。
- 不支持用户创建样机模板。
- 不使用生成模型重画 Logo、符号或 IP 来冒充严格样机。
- 不把智能编排退化为扁平整图生成。
- 不静默覆盖源文件、旧结果、当前画布或已有定稿。

## 14. 成功标准

本设计完成实施后，用户应能够：

1. 不创建项目，选择单图或文件夹批量抠图，并在独立结果目录中获得保持原相对结构的逐图结果。
2. 同时运行或排队多个作业，清楚看到每张图的状态、结果和失败原因。
3. 在画布中明确选择图片图层，使用背景、延展和修复工具，而不破坏其他可编辑图层或保护区域。
4. 使用核心物料和视觉参考生成可继续编辑的结构化设计候选。
5. 使用内置模板把 Logo、符号或 IP 制作成保真、可替换源资产的样机设计文档。
6. 在所有流程中看到真实提供方、上传范围、状态和可验证结果，不遭遇静默模型替代、付费重试或内容覆盖。
