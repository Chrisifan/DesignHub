# DesignHub 批量图像工具 UI 设计简报

日期：2026-09-28
面向：UI/UX 设计师、交互设计师、产品设计评审
来源：`2026-09-20-image-tools-and-creative-workflows-design.md`、`2026-09-28-complete-feature-closure.md` 及当前图像工具域模型

## 1. 这份简报解决什么问题

批量图像工具面向“只想处理本地文件并拿到结果”的用户，不要求先创建项目或打开画布。用户可以选择一张图片或一个文件夹，固定一个工具和一套参数，创建一个独立作业，并在结果中心查看每张图片的处理状态。

产品主线是：

```text
图像工具 → 新建作业 → 选择来源 → 扫描确认 → 选择输出位置
→ 执行作业 → 查看逐图结果 → 打开/显示/导入结果
```

批量作业与项目画布是两条入口，但共享 provider、任务状态、素材和恢复语义。批量结果是文件，不自动创建项目、文档或画布修订。

## 2. 设计师先记住的产品边界

### 2.1 首批批量工具

一级“图像工具”首批应展示：

| 工具 | 结果 | 是否需要 provider | 设计重点 |
| --- | --- | --- | --- |
| 去除背景 | 每张图片一个透明结果文件 | 是 | 透明度校验、失败不改为有底色 |
| 放大图像 | 每张图片一个放大结果文件 | 是 | 目标倍率/尺寸限制、结果尺寸展示 |
| 尺寸转换 | 本地生成新尺寸文件 | 否 | 宽高、格式、原文件不覆盖 |
| 格式转换 | 本地生成新格式文件 | 否 | PNG/JPEG/WebP、透明图转 JPEG 时需要背景 |

画布专用工具（如局部重绘、移除对象、扩展画布、去除水印）可以继续存在于 Workbench 检查器，但不应因为共享 allowlist 就全部出现在批量页面首屏。

### 2.2 一个作业只做一件事

一个作业固定：

- 一个工具；
- 一套参数；
- 一个单图或文件夹来源；
- 一个用户选择的输出位置；
- 一个可编辑的结果文件夹名；
- 多个逐图处理项。

首版不提供同一作业内的“去背景 → 放大 → 转格式”流水线。用户可以从上一次结果创建下一次作业。

### 2.3 不做的事情

- 不覆盖原文件或旧作业结果；
- 不自动全图或文件夹去水印；
- 不让用户设置线程数、并发数或底层调度策略；
- 不自动切换 provider 或模型；
- 不因应用重启而自动重新提交可能计费的请求；
- 不把批量结果静默写入当前画布或项目修订。

## 3. 信息架构与页面骨架

### 3.1 一级导航

主导航在“素材库”附近增加“图像工具”。页面标题建议：

- 中文：`图像工具`
- 英文：`Image tools`
- 页面 eyebrow：`批量处理` / `Batch processing`

页面采用稳定的主从结构：

```text
┌─────────────────────────────────────────────────────────────┐
│ 页面标题                         [新建作业]                 │
├───────────────┬─────────────────────────────────────────────┤
│ 作业列表       │ 当前作业标题 / 状态 / 总进度                 │
│ 活跃           │ 工具参数、来源、输出目录摘要                 │
│ 最近           │ ┌────┬────┬────┬────┐                     │
│ 已归档         │ │图 1│图 2│图 3│图 4│ 逐图结果网格             │
│               │ └────┴────┴────┴────┘                     │
│               │ 选中项详情抽屉 / 原图与结果对比               │
└───────────────┴─────────────────────────────────────────────┘
```

桌面窗口使用左侧作业列表、右侧详情；窄窗口改为上下结构：先显示作业选择和摘要，再显示结果网格。旧作业按时间归档，不使用长期堆积的临时标签页。

### 3.2 作业列表

每行至少显示：

- 工具名称和图标；
- 作业结果文件夹名；
- 聚合状态；
- 完成数 / 总数；
- 最近更新时间；
- 当前是否有失败项或未知项。

列表支持“活跃 / 最近 / 已归档”分组或筛选。切换作业不停止其他作业，当前详情应保存用户的选中处理项。

## 4. 新建作业流程

新建作业可以使用对话框或右侧抽屉，但必须按以下顺序组织信息。不要让用户在尚未选择来源前填写大量参数。

### Step 1：选择工具

工具选择使用菜单或选择卡，不使用一组同时展开的复杂表单。选择后显示一句结果说明，例如：

- `去除背景：输出透明背景图片`
- `放大图像：使用已配置的图像连接处理`
- `尺寸转换：在本机生成新文件`
- `格式转换：在本机转换文件格式`

仅显示当前批量页面支持且当前连接可用的工具。provider 不支持某个工具时，应保留用户当前选择和已填参数，但显示“连接设置”恢复入口并禁用执行。

### Step 2：选择来源

提供两个明确入口：

- `选择图片` / `Choose image`
- `选择文件夹` / `Choose folder`

原生选择器只由主进程调用。选择后先进入扫描状态，再显示来源摘要：

- 可处理数量；
- 被拒绝数量；
- 拒绝原因汇总；
- 预计输出目录结构；
- 预计使用的 provider、模型和上传范围（需要远端处理时）。

文件夹扫描默认不跟随符号链接。无权限、循环链接、不支持格式和路径冲突必须逐项可查看，不能只显示一个“扫描失败”。

空目录是可恢复状态：显示空目录说明和“重新选择来源”，不创建可执行作业。

### Step 3：设置参数

只展示当前工具的参数。参数面板需要包含：

- 工具专属输入；
- 当前连接和模型（远端工具）；
- 能力限制，如最大尺寸、最大文件大小、透明输出支持；
- 参数范围和校验提示；
- 上传提示：哪些图片会发送给哪个 provider。

本地工具不应出现 provider 选择。所有参数在创建作业后冻结，逐项结果不能被单独改成另一套参数。

### Step 4：选择输出

提供：

- 输出目录选择器；
- 自动建议的作业结果文件夹名；
- 可编辑的文件夹名；
- 输出结构预览。

示例：

```text
选择的输出目录/
  商品图抠图-20260920-1430/
    鞋类/
      正面/
        a.png
```

默认生成新的作业目录，禁止覆盖原文件和旧结果目录。输出目录必须与来源根目录不同。

### Step 5：确认创建

确认区只需要回答三个问题：

1. 将处理多少张图片？
2. 结果会写到哪里？
3. 是否会上传到 provider？

主按钮文案：`创建作业` / `Create job`。创建后进入作业详情并开始排队；不要在点击后重新打开一个没有状态反馈的空白页面。

## 5. 作业详情与逐图结果

### 5.1 顶部摘要

当前作业详情顶部显示：

- 工具和参数摘要；
- 来源类型与来源根目录（路径过长时截断，支持 tooltip 和复制）；
- 输出结果目录；
- provider / 模型（远端工具）；
- 完成数、失败数、未知数和总数；
- 进度条和聚合状态。

操作按钮按状态显示：

- 排队 / 运行中：`暂停`、`取消`；
- 已暂停：`继续`、`取消`；
- 有失败或未知项：`重试失败项` 或逐项 `重试`；
- 已完成：`打开结果文件夹`、`导入素材库`；
- 部分失败：保留已成功结果，同时强调失败项，不回滚成功文件。

### 5.2 结果网格

每个处理项使用固定尺寸卡片，避免状态文案改变布局。卡片包含：

- 来源相对路径；
- 原图缩略图或文件图标；
- 当前状态；
- 结果缩略图（完成后）；
- 尝试次数；
- 错误码或简短失败原因；
- 进入详情的按钮。

网格至少支持按状态筛选：全部、排队、处理中、完成、失败、已取消、结果未知。长路径在卡片内截断，完整路径放入 tooltip/详情抽屉。

### 5.3 处理项详情抽屉

选中处理项后打开抽屉，抽屉显示：

- 原图与结果图切换；
- 并排比较或 before/after 滑块；
- 来源相对路径、结果路径和作业目录；
- 该项的工具参数、尝试记录、错误码；
- provider、模型和远端 request ID（若有）；
- 关联“模型任务”入口；
- 文件操作。

完成结果的文件操作：

- `打开文件` / `Open file`；
- `在文件夹中显示` / `Reveal in folder`；
- `打开结果文件夹` / `Open result folder`；
- `导入素材库` / `Import to asset library`。

“导入素材库”必须是明确动作，不因预览结果而自动导入。

## 6. 状态、操作与恢复文案

### 6.1 处理项状态

| 状态 | 用户看到什么 | 可用动作 |
| --- | --- | --- |
| 排队 `queued` | 等待处理 | 等待、取消作业 |
| 处理中 `running` | 当前正在处理 | 查看任务、取消作业 |
| 完成 `completed` | 结果已发布并通过校验 | 打开、显示、导入 |
| 失败 `failed` | 该项未产生有效结果 | 查看原因、显式重试 |
| 已取消 `cancelled` | 该项未继续处理 | 显式重试 |
| 结果未知 `unknown` | 应用无法确认远端结果 | 查询、远端取消或承担风险后重试 |

“结果未知”不能使用“失败”替代。文案必须说明：可能已经产生远端计算或费用，应用不会自动重发。

### 6.2 父作业聚合状态

父作业显示：等待、运行中、已暂停、已完成、完成但有失败项、已取消。设计上要保留“成功结果仍可用”的信息，部分失败不应让整个结果区变成错误页。

### 6.3 典型错误与恢复入口

| 情况 | 页面反馈 | 恢复动作 |
| --- | --- | --- |
| 未配置 provider | 连接缺失，不能创建远端作业 | 打开连接设置 |
| provider 不支持工具/透明输出 | 明确说明能力不足 | 选择支持的连接或改用本地工具 |
| 限流 | 显示连接被限流及 retry-after | 等待继续，不静默换模型 |
| 坏响应/空结果 | 该项失败并保留错误码 | 从持久化源素材重试 |
| 应用重启 | 运行中项变为未知或暂停 | 查询、取消或确认风险后重试 |
| 目录不可读 | 单项拒绝，不影响可读项 | 修复权限后重新选择/重试 |
| 符号链接/路径穿越 | 扫描阶段拒绝 | 查看被拒绝项，不执行危险路径 |
| 磁盘写入失败 | 结果未发布，保留可恢复错误 | 更换输出目录后重试 |
| 输出目录已移动 | 文件操作失败但作业记录保留 | 重新定位或打开当前可用目录 |

## 7. 调度和并行作业的可见行为

用户不需要看到线程数或并发配置，但需要知道作业没有被“卡死”：

- 多个作业可以同时存在并排队；
- 大文件夹不能长期独占连接，多个作业按稳定顺序轮转；
- 当前连接限流时，相关作业显示“等待连接恢复”；
- 暂停只停止安排新项，已运行请求按 provider 能力继续或请求取消；
- 取消会取消未开始项，已经成功发布的文件保留。

## 8. 与“模型任务”的联动

图像工具页面负责业务层作业和逐图结果，“模型任务”页面负责所有 provider 请求的统一运行视角。两处不得各自维护一份状态。

模型任务详情应提供：

- 返回父作业；
- 定位具体处理项；
- provider、模型、能力、request ID；
- 取消/查询支持情况；
- 上传范围与费用未知提示。

从模型任务跳回图像工具时，应自动选中对应作业和处理项，而不是只回到页面首页。

## 9. 视觉、响应式与可访问性要求

- 支持中文/英文，状态、错误、工具名称和按钮均需成对维护；
- 支持明亮/深色主题，状态不能只依赖颜色，必须同时有文字或图标；
- 结果网格和作业列表在窄窗口下仍保留暂停、取消、重试和打开结果等关键动作；
- 所有图标按钮提供 tooltip 和可访问名称；
- 作业列表、结果网格、状态筛选和详情抽屉可用键盘完成；
- 进度条使用可访问的 `progressbar` 语义，并朗读当前完成数；
- 错误信息贴近出错控件，不能只放在 toast；
- 长路径、长文件名和双语长文案不能撑破卡片或遮挡操作；
- 图片缩略图加载失败时显示文件类型/错误占位，不影响其他处理项；
- 大批量结果采用固定卡片尺寸和可滚动区域，避免页面因缩略图加载不断跳动。

## 10. 技术约束对设计的影响

这些内容不需要设计师决定实现方式，但会限制交互：

1. 公共运行时身份使用 `libraryId`；批量作业不能重新引入 workspace 生命周期概念。
2. 原图、结果图和 mask 二进制进入受管素材或输出目录，不长期存放在 renderer 状态或 TaskRecord 中。
3. 作业和处理项需要可持久化，应用重启后页面能恢复历史状态。
4. 相对路径必须安全规范化：拒绝绝对路径、`..`、控制字符、保留设备名和越界路径。
5. 结果先写临时文件，经过格式、尺寸和透明度校验后原子发布；只有发布成功才显示“完成”。
6. 每次重跑使用新的作业结果目录，原文件和旧结果不覆盖。
7. 结果未知不自动创建修订、不自动重新提交；所有重试都是用户显式操作。
8. 真实 provider、Windows 原生选择器、签名、公证、Keychain 和人工画质仍是独立验证门禁。

## 11. 当前实现状态（2026-09-28）

### 已有，可作为设计对齐基础

- `ImageToolJob` / `ImageToolItem` 类型，包含工具、参数、来源根目录、输出根目录、逐项状态、尝试次数和结果路径；
- 作业聚合状态、相对路径安全校验和失败/取消/未知项显式重试规则；
- 原子 JSON 作业存储，可用于重启恢复；
- `ImageToolsPage` 页面骨架，已包含工具选择、作业列表、暂停/继续、取消、失败项重试和打开结果入口；
- provider 具体工具能力模型、mask 元数据和 `unknown` 任务语义。

### 尚未接通，设计稿不要假定已经可用

- 原生单图/文件夹选择器及扫描预览；
- 批处理 worker、真实执行队列和跨作业公平调度；
- 暂停/继续/取消与真实 provider 的 IPC 闭环；
- 结果文件原子发布、格式/透明度校验和结果导入素材库；
- “在文件夹中显示”“打开结果文件夹”等原生文件操作；
- 作业与模型任务的双向定位；
- 完整的逐图结果网格、详情抽屉、对比预览和错误筛选；
- 批量 `remove-background` 的真实 provider 质量、费用和远端取消验证。

当前自动化已证明域模型和原子存储基础，不等于批量 UI 或真实文件处理链路已经交付。

## 12. 设计交付验收清单

- [ ] 新建作业可以在一个流程中选择工具、来源、参数和输出目录；
- [ ] 扫描预览清楚区分可处理、被拒绝和空目录；
- [ ] 桌面端呈现“作业列表 + 当前作业结果网格”；窄窗口仍可操作关键动作；
- [ ] 逐图卡片覆盖排队、处理中、完成、失败、取消、未知六种状态；
- [ ] 处理项详情能比较原图/结果并显示错误、provider、模型和路径；
- [ ] 部分失败不会隐藏已成功结果；
- [ ] 暂停、继续、取消、重试和导入素材库都有明确状态反馈；
- [ ] 未知结果不会被设计成自动重试或普通失败；
- [ ] 长路径、双语、深色主题、键盘操作和无障碍状态均有方案；
- [ ] 画布工具与批量工具的入口和结果边界清晰，不把文件结果误认为项目修订。
