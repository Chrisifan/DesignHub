# 作品集设计师四步向导设计

## 目标

将作品集创建设计师流程收敛为四个不可跳过的阶段：导入作品、特征解构、形象生成、审阅发布。解析完成后必须停留在第二步，使用户能够检查和编辑风格档案，而不是直接进入最终发布。

## 流程与状态

新建设计师向导使用 `import`、`analyse`、`avatar`、`review` 四个状态：

1. `import`：检查作品集来源、选择图片并确认分析权利，提交视觉分析任务。
2. `analyse`：显示模型生成的设计师名称和完整视觉 DNA。用户可编辑名称、署名、摘要、原则、标签、色板、排版、构图、材质和禁用规则。可追加作品集并重新解析。
3. `avatar`：基于第二步最终草稿提交形象生成任务，展示一个或多个可选择的形象。未选择形象不能前进。
4. `review`：显示选定形象与完整设计师档案，提供最终预览与发布。只有此状态允许发布。

步骤导航仅反映当前状态，不作为随机跳转控件。前进使用底部主按钮；在第二步可返回导入，在第三步可返回特征解构，在第四步可返回形象选择。

## 设计师名称与重新解析

视觉分析提示词要求模型根据综合色彩、排版、构图、材质与规则生成描述风格的原创设计师名称，不能使用通用占位名。解析结果沿用现有 `PersonaProfile` 字段，名称写入 `name`，其余风格数据写入现有字段。

第二步的编辑只修改会话内的解析草稿，不会创建或发布设计师。追加来源时，用户在新的来源检查批次中选择图片；向导保留此前所有已选来源，并将它们与新来源聚合后提交一轮视觉分析。新结果整体替换第二步草稿，包括之前手工编辑的所有字段；旧结果不合并、不保留，也不发布。

## 形象与发布

形象生成提示词从第二步草稿构建，保证名称与视觉 DNA 一致。生成任务完成后把受管图片作为形象选项显示在第三步，选择一个选项才可进入第四步。第四步发布时，创建单个 `published` `PersonaProfile` 并持久化；流程中不会提前把候选写入设计师库。

## 错误与恢复

- 视觉分析失败或返回不完整候选时保持在导入/特征解构上下文，显示失败提示，绝不进入形象或发布阶段。
- 追加来源重新解析失败时保留当前第二步草稿和编辑内容，允许修正来源后重试；只有成功返回的新完整结果才整体替换草稿。
- 形象生成失败时停留在第三步，保留第二步草稿和已有形象选项，可重试生成或返回编辑。
- 关闭向导会丢弃未发布的会话草稿，与当前新建流程一致。

## 界面

沿用当前工作区内的宽抽屉与固定页脚动作区。第二步采用参考图的密集分区：身份与理念、色彩、排版与构图、材质、禁用规则。字段使用现有输入、文本域、色板和标签编辑交互，避免新增另一套表单体系。追加作品集是第二步的次级操作；“下一步：生成形象”是唯一主操作。

## 测试

- 单元测试验证解析后的名称显示于第二步，第二步可编辑并且不能发布。
- 验证追加解析成功会整体替换编辑草稿，失败则保留原草稿。
- 验证第二步前进会提交形象生成，第三步必须选择形象后才可进入第四步。
- 验证第四步才可发布，并保持现有受管图片持久化行为。
- 运行设计师库聚焦测试、完整单元测试、类型检查和 lint。

## 非目标

- 仅扩展作品集分析提交以支持聚合多个已检查批次；不改变来源检查、权限确认、任务持久化或图片资产存储协议。
- 不为未发布草稿新增跨应用重启持久化。
- 不在本次修改中实现多设计师候选的合并或历史版本比较。
