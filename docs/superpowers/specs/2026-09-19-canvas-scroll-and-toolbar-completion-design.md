# 画布滚动与工具栏补全设计

## 目标

让超大画布保留双轴滚动能力但不显示滚动条；新生成占位稿进入布局后必须精确滚动到画布可视区域中心；顶部缩放工具统一作用于正式稿、候选稿和生成占位稿；补全右侧属性按钮在无选择时的行为。

## 交互设计

- `.workbench-canvas__stage` 继续作为唯一滚动容器，隐藏 WebKit、Firefox 和旧式滚动条，但保留滚轮、触控板与程序化滚动。
- 不再依赖 `scrollIntoView()`。候选面板在最新运行任务挂载后，把目标元素交给画布层；画布层根据目标与滚动容器的 `getBoundingClientRect()`、当前 `scrollLeft/scrollTop` 计算中心位置，并调用 `scrollTo()`。
- 居中在占位稿首次出现时执行；任务完成并替换为图片时不重复跳动。
- 顶部缩小、放大统一改变所有稿件的展示宽度。稿件保持文档宽高比，正式稿内部画布继续使用 fit 模式，避免双重缩放。
- 重置缩放恢复基准展示宽度，并将选中候选、最新生成任务或当前正式稿重新居中。
- 网格继续始终显示，按钮保持只读开启状态。
- 右侧属性按钮在真实文档中优先重新打开当前检查器；没有选择时自动选择第一个可编辑图层；完全空文档则显示“当前没有可编辑图层”的提示。
- 对话、历史、工具、定稿、导出和返回保持现有实现。

## 边界

- 不改变任务、候选和 revision 数据模型。
- 不保存画布滚动位置和展示缩放值。
- 不改变设计稿自由拖动偏移的存储方式。
- 不恢复可关闭网格。

## 验收

- CSS 中滚动条不可见，`.workbench-canvas__stage` 仍为 `overflow: auto`。
- 新运行任务挂载后对正确滚动容器调用 `scrollTo()`，计算结果同时改变横纵坐标。
- 缩放按钮改变正式稿、候选稿和占位稿宽度；重置后恢复并居中。
- 属性按钮在无选择但存在图层时打开第一个图层检查器；空文档给出提示。
- Workbench、CandidateBoard、CanvasWorkspace 测试、类型检查、lint 和 build 通过。
