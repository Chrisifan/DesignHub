# 单一项目库目录设计

## 目标

移除用户可见的“工作区”层级。首次启动由用户选择一个项目库目录；此后 DesignHub 直接打开这个目录，并以目录中的项目作为唯一项目区分方式。

每个项目仍有独立项目目录和项目数据库。设计师、品牌、共享素材索引、任务历史和回收站由项目库统一管理。应用本机模型连接配置和凭据继续留在本机配置与系统安全存储中。

## 已确认的产品决策

- 首次启动显示项目目录引导，由用户选择目录。
- 用户所选目录本身就是项目库根目录；应用不再在其下创建一个命名工作区。
- 空目录可以初始化为项目库；已初始化的项目库可以直接打开。
- 对未知的非空目录不自动初始化、不覆盖、不收纳其中现有文件。
- 应用保存唯一项目库路径，后续启动直接进入项目首页。
- 常规菜单和首页不提供工作区或项目库切换入口。
- 项目库路径失效时进入恢复引导：用户重新定位原项目库，或明确选择开始使用一个新目录；不得静默创建空库。
- 旧工作区忽略：不扫描、不自动打开、不迁移、不修改。原目录保持不动；项目包手动导入能力继续保留。
- 任务历史和回收站在整个项目库内共享，而不是每个项目各一份。任务保留所属项目上下文；回收站统一管理删除的项目。
- 界面不暴露“工作区”术语；项目库身份仍作为主进程 IPC、任务和写入边界使用。

## 用户流程

### 首次启动

1. 应用本机配置没有有效项目库路径时展示首次启动引导。
2. 用户选择目录后，主进程解析规范路径并检查目录身份和内容。
3. 空目录按项目库格式初始化，写入带版本号的项目库清单及受管目录，然后打开项目首页。
4. 已包含有效项目库清单的目录直接打开。
5. 未识别的非空目录显示具体原因并允许重新选择，不对该目录做写入。

### 后续启动与恢复

应用从受信的本机配置读取已保存的目录并直接打开项目库。若目录不存在、不可访问、身份校验失败或格式无法安全打开，则显示恢复引导。界面不把失败路径悄悄替换成空项目库，也不读取旧版最近工作区列表。

项目库正在被另一个 DesignHub 实例以写模式打开时，沿用单写者锁和现有只读降级/错误语义。项目库身份、规范路径和目录文件系统身份在主进程重新校验后才授予写入能力。

## 存储结构与所有权

项目库根目录由用户选择。目录内的受管结构沿用现有可复用布局：

```text
<项目库目录>/
  designhub.library.json
  projects/<project-id>/
  shared-assets/
  trash/
  .designhub/
```

具体内部文件仍由对应存储模块拥有，不要求用户手动维护。

- `projects/<project-id>/` 保存项目清单、项目数据库、文档、素材及不可变历史；项目之间继续隔离。
- 库级 `.designhub` 数据保存项目索引、写锁、共享设计师/品牌数据、任务状态、搜索索引和设置等。
- `trash/` 是项目库唯一回收站，集中管理软删除项目及其恢复元数据。
- 任务历史是跨项目的单一列表，记录仍关联各自的项目/文档上下文。
- 模型端点配置仍在应用 `userData`；凭据仍只进入操作系统安全存储，不复制进项目库。

项目库清单有独立类型标识和正整数格式版本。不能把旧 `designhub.workspace.json` 当作新库清单，也不能从其路径自动推断或打开项目库。项目库格式升级沿用现有可追踪迁移、备份和前向兼容原则。

## 架构边界

### 主进程

新增项目库初始化、打开和恢复定位的受信入口。主进程负责：

- 选择目录后的规范路径解析与目录身份检查。
- 空目录初始化、项目库清单校验和受管目录验证。
- 唯一项目库路径的本机持久化。
- 单写者锁、只读模式及后续每次写入的项目库 lease 校验。
- 在所有 IPC handler 中使用活动项目库身份和 handle，不接受渲染层自报的任意根目录作为写入权限。

现有 `WorkspaceHandle`、工作区 IPC 和项目库依赖边界需迁移为语义明确的项目库接口。业务操作继续通过主进程委托给项目、素材、修订、任务、设计师、品牌、备份和检索存储，不由渲染层拼接文件路径。

### 渲染层

- 首次引导复用现有 Welcome/应用入口结构，但删除“新建工作区”“打开工作区”和最近工作区列表。
- 项目库初始化成功后直接加载现有首页。
- 移除窗口栏工作区名称及切换控件。
- 项目、项目详情和画布继续使用现有导航与数据流。
- 不添加常规切换项目库菜单，也不借本次变更重做首页布局。

### 本机路径偏好

新的唯一项目库目录由 Electron 主进程保存于应用 `userData` 配置。旧 `localStorage` 最近工作区键不参与新启动决策；读取旧 key 也不得触发打开、迁移、扫描或修改。

## 错误处理与安全

- 目录选择取消：停留引导，不创建任何文件。
- 空目录初始化失败：报告明确错误；保证可以安全重试，不留下会被识别为完整项目库的半成品。
- 未知非空目录：拒绝初始化且不修改现有内容。
- 已记住的目录暂时不可用：进入恢复引导，保留原路径供重新定位，不自动替换。
- 格式版本高于当前应用：遵循只读兼容或拒绝打开语义，不尝试降级迁移。
- 写锁冲突：不能授予并发写权限；沿用现有只读/忙碌呈现。
- 所有 IPC 写入继续执行来源、活动库身份、写权限及目标项目上下文校验。
- 旧工作区绝不作为初始化候选，不探测其中是否有可导入项目。

## 不在本次范围

- 自动搜索、迁移或转换旧工作区内容。
- 同步、共享盘并发写、云端项目库或多项目库切换。
- 将项目目录改成独立于项目库、可任意注册的全局项目集合。
- 改造项目内容格式、项目包格式、任务语义或项目编辑体验。
- 删除用户旧工作区目录。

## 验收与测试

### 项目库存储与启动

- 首次选择空目录后创建有效项目库并进入项目首页。
- 取消选择不会写入任何文件。
- 选择已有项目库后恢复原项目、项目库资料、共享任务历史和回收站。
- 应用重启直接打开已记住的项目库；旧最近工作区 localStorage 数据不会改变目标目录。
- 未知非空目录拒绝初始化，目录内容逐字节不变。
- 初始化中途失败可重试，不能留下有效清单却缺少必要结构的半成品。
- 项目库被移动/原路径失效后能重新定位；不能静默创建新库。
- 两个实例的写锁冲突和只读语义正确。
- 新库身份与旧工作区清单严格区分；测试确认旧工作区不被扫描、打开或改写。

### 项目与共享数据

- 在同一个库中创建、列出、重开多个独立项目，项目数据库和内容互不串扰。
- 多项目任务进入一个共享任务历史，并保留正确的项目关联。
- 多项目删除项进入一个共享回收站，可恢复到原库项目列表。
- 项目包手动导入仍能添加项目；不会据此扫描任何旧工作区。
- 设计师/品牌、设置、搜索索引和素材相关现有存储契约在项目库上下文下继续工作。

### 界面与桥接

- Welcome 不显示创建/打开工作区或最近工作区入口。
- 窗口栏不显示工作区名称和切换按钮。
- 没有项目库时展示选择引导；项目库不可访问时展示恢复流程。
- 项目首页、项目详情、画布和设置/资源页面不出现工作区切换体验。
- IPC 只接受主进程当前活动项目库身份，渲染层不能借传入其他路径越权。

### 回归

运行受影响的项目库/项目存储、主进程 IPC、preload bridge、App/Welcome/Studio 首页与项目包测试；再运行 typecheck、lint、集成与端到端测试、构建和 `git diff --check`。平台打包按既有 Windows/macOS 验收门槛记录，不把未执行的平台测试报为通过。
