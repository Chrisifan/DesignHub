# 项目详情页封面与摘要聚合设计

## 目标

在不改变项目数据和操作能力的前提下，缩小项目详情页顶部封面占用，并将标题、简介、设计署名、保存位置与主要操作聚合为一个连续的项目头部。解决当前封面过高、标题区与封面割裂、摘要信息分散的问题。

## 选定方案

采用“封面与信息卡一体”的 B 方案：顶部由一张完整的项目头部卡片承载封面和信息，而不是继续使用相互分离的 Hero 与摘要区。

- 卡片上部为紧凑封面。
- 卡片下部为统一信息区。
- 封面与信息区共享边框、圆角和背景，形成单一视觉单元。
- 详情页其余文档区和右侧信息栏保持现有结构与功能。

## 页面结构

### 项目头部卡片

- 桌面端封面使用固定区间高度，目标高度为 `240px`，允许在紧凑窗口内收缩至 `220px`，不再随视口宽度增长到 `440px`。
- 封面继续使用 `ProjectCoverImage`，保持居中裁切、项目封面资产读取和默认封面回退逻辑。
- 文档数量标签保留在封面内部，但不再在封面内重复放置“打开画布”按钮。
- 信息区紧接封面下方，与封面共用外层卡片边界。

### 信息分组

- 信息区使用左右两组布局。
- 左侧依次展示项目状态、标题、简介和元信息。
- 标题字号收敛到桌面端约 `30–36px`，保持单一主标题层级。
- 简介最多显示两行，溢出以省略号处理；无简介时显示本地化占位文案并保留相同的两行高度。
- 设计署名和保存位置位于同一条元信息行，保持紧凑间距。
- 无设计师时显示“未设置设计师”，但不改变元信息区域高度。
- 右侧集中展示“打开画布”和“导出交付”，按钮与标题信息垂直居中，避免游离在独立摘要块中。

## 交互与数据

- “打开画布”继续打开主文档；无文档时不显示该操作。
- “导出交付”继续使用现有回调。
- 项目状态、设计师版本、贡献者署名和保存状态继续从现有 `ProjectDetailPage` 属性推导。
- 不新增项目字段，不改变封面、设计师、文档或导出的持久化流程。
- 页面顶部已有项目管理工具栏保持不变。

## 响应式行为

- 宽窗口中，信息内容和操作使用 `minmax(0, 1fr) auto` 双列布局。
- 中等宽度窗口中，封面保持约 `220px` 高度，信息区内边距适度收紧。
- 窄窗口中，信息区改为单列：操作按钮排列在元信息下方并允许换行。
- 移动宽度下封面高度约为 `180px`，避免占据大部分首屏。
- 所有断点都保留简介两行空间和设计师区域的稳定高度，避免不同项目之间出现垂直跳动。
- 页面不得产生横向滚动。

## 视觉规则

- 外层卡片使用现有表面色、边框、阴影和圆角 token，不引入新的品牌色。
- 封面与信息区之间使用细分隔线，不拆成两张独立卡片。
- 信息区背景提供稳定对比度；深色、浅色和降低透明度模式均沿用现有主题变量。
- 收紧标题、简介和元信息之间的垂直间距，使其被识别为同一信息组。
- 主要操作与次要操作保持现有按钮语义和可访问状态。

## 组件调整

- `ProjectDetailPage.tsx`：将现有 `project-detail-hero` 与 `project-detail-summary` 合并到同一个项目头部容器，移除封面内重复的“打开画布”按钮。
- `project-detail.css`：重写头部卡片、封面高度、信息分组和响应式规则。
- `ProjectDetailPage.test.tsx`：更新结构断言，验证头部只保留一个打开画布入口，并覆盖无简介、无设计师和无文档状态。
- 其他页面、数据模型和桌面主进程不在本次改动范围内。

## 错误与空状态

- 封面资产加载失败时继续显示默认封面。
- 无简介时显示占位文案且保留两行高度。
- 无设计师或设计师版本时显示明确的未设置状态，不隐藏区域。
- 无文档时隐藏“打开画布”，其余项目信息正常显示。
- 只读状态不改变头部信息布局；现有权限逻辑继续决定可用操作。

## 测试与验收

- 项目头部渲染为单一卡片，封面和摘要不再是两个分离区块。
- 宽屏封面高度不超过 `260px`，移动宽度不超过约 `180px`。
- 页面中只出现一个有效的“打开画布”主操作。
- 标题、两行简介、设计署名、保存位置和操作在信息区内形成稳定分组。
- 有无简介、有无设计师时，头部信息的关键行高保持一致。
- 窄窗口下操作区换行后不产生横向溢出。
- 现有打开文档、导出、封面回退和本地化行为不回归。
- 运行详情页组件测试、Studio 相关测试、类型检查、Lint 和构建。

## 边界

- 不增加封面编辑入口。
- 不改变项目详情页下方文档和侧栏的信息架构。
- 不新增项目统计或虚构状态。
- 不修改画布、对话生成、任务链路或 revision 行为。
