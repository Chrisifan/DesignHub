Registry metadata and GitHub repository APIs were queried on 2026-09-09. Popularity or an available prebuild is not a product verification result.

Task 3 repository pages and maintained API documentation were inspected in Chrome on 2026-09-10: `https://github.com/sindresorhus/trash`, `https://github.com/jprichardson/node-fs-extra/blob/master/docs/move.md`, and `https://nodejs.org/api/fs.html#fspromisesrenameoldpath-newpath`. No new dependency is required for Task 3, so `package.json` remains unchanged.

Task 4 adoption check on 2026-09-10 used the installed `better-sqlite3` implementation and type declaration. M02 uses a complete, verified directory backup with an explicit completion marker, not a partial archive or a raw live-database copy. No new dependency is required, so `package.json` remains unchanged.

The Task 4 artifact keeps only workspace-relative directory and file entries plus SHA-256 hashes. Known M02 SQLite locations use online backup and are normalized to rollback-journal mode before final verification, so transient journal/WAL/SHM files and `.designhub/writer-lock.sqlite` are not domain entries. `.designhub` is a fail-closed M02 namespace: only the regular-file project index and the known transient SQLite files are recognized during source enumeration, and any other file or directory rejects backup with `UNMANAGED_INTERNAL_FILE`. Restore recreates the writer-lock database before publishing the workspace manifest. Provider credentials remain in operating-system secure storage under ADR 0015 and are outside the workspace backup closure; this allowlist does not inspect or claim protection for arbitrary credential-like files outside `.designhub`. Future internal domain files require an explicit closure-policy update and regression tests before adoption.

Periodic backup configuration and missed-interval prompts belong to the later accepted workspace/settings UI delivery. A future scheduler may run only while the application is running and the selected destination is available; there is no independent exit-time daemon guarantee. This task intentionally provides the verified storage operation only and does not add an unused schedule/configuration surface.

## Task 1 format boundary

- A new workspace is a newly-created child directory under a user-selected parent. An existing child directory is never reused or overwritten.
- `designhub.workspace.json` is the minimal compatible manifest: kind, stable workspace ID, display name, positive integer format version and creation timestamp.
- `.designhub/writer-lock.sqlite` is implementation metadata. `projects/`, `shared-assets/` and `trash/` are visible domain containers.
- Paths locate a workspace; the manifest ID identifies it. Moving the whole directory must retain the same ID.
- A format newer than the application-supported version is parsed only through the known manifest and opened read-only. No unknown database is created or migrated.
