# DesignHub UI 基础规范

状态：已确认。确认日期：2026-09-09。适用范围：macOS / Windows Electron 桌面端首版。

本文把已确认的 Figma 参考、明暗主题说明和产品交互约束整理为可执行的 UI 基线。它不新增产品功能，也不替代页面流程说明；业务范围仍以[应用说明书](APPLICATION-GUIDE-FOR-UI.md)为准。

## 1. 设计依据与优先级

| [暗色主题说明](DESIGN-DARK.md) | 暗色语义色、材质和状态颜色 | 独立于明亮主题的另一套布局 |
| [明亮主题说明](DESIGN-LIGHT.md) | 明亮语义色、材质和状态颜色 | 复用 Figma 中非 DesignHub 的浅色页面 |
| 本文 | 跨主题布局、字体、窗口、组件、国际化、动效和验收规则 | 新业务能力 |

出现冲突时按下列顺序处理：

1. 业务功能和状态以应用说明书为准。
2. DesignHub 页面结构和视觉关系以本文列出的 Figma 节点为准。
3. 颜色实现值以主题文档 frontmatter 的 `colors` 语义 token 为准；正文中的近似色只说明视觉方向。
4. 字体、间距、尺寸、响应式和可访问性以本文为准，并在两套主题之间保持一致。
5. Electron 或操作系统的真实能力限制优先于静态稿；差异必须记录并提供降级，不能静默删去操作。

## 3. 体验与视觉原则

DesignHub 的整体气质是“专业创作工作站”：精密、安静、高密度、内容优先。界面要让用户把注意力放在画布、素材和设计决策上，而不是装饰性容器。

- 使用清晰的 1px 分隔线、有限的层级表面和稳定的 4px 网格。
- 通过明度、边界和少量阴影表达层级，不把每组内容都包装成悬浮卡片。
- 常用工具紧凑但仍可点击和键盘访问；低频信息按需进入抽屉、Popover 或详情区。
- 青色承担暗色主题中的常规主操作和选择；紫色优先表达 AI、生成或推理；绿色表达就绪与完成；黄色和红色只表达风险与错误。
- 画布与作品图像保持视觉中心，状态和运行指标不得长期占据比作品更强的视觉权重。
- 同一业务状态在明暗主题中保持相同位置、组件形态和交互，只改变语义颜色与材质。

## 4. 主题与颜色体系

应用提供“跟随系统、深色、浅色”三种选择并记住用户设置。首次启动默认跟随系统。系统主题变化可以更新界面，但不能中断输入、关闭浮层或重置画布状态。

两份主题文档 frontmatter 中的语义 token 是颜色实现的唯一基础。以下为核心映射：

| 语义角色 | 暗色 | 明亮 |
| --- | --- | --- |
| 应用背景 | `background` `#0f131c` | `background` `#faf8ff` |
| 最深/最亮底层 | `surface-container-lowest` `#0a0e17` | `surface-container-lowest` `#ffffff` |
| 导航与低层面板 | `surface-container-low` `#181b25` | `surface-container-low` `#f2f3ff` |
| 标准面板 | `surface-container` `#1c1f29` | `surface-container` `#eaedff` |
| 悬浮或交互面 | `surface-container-high` `#262a34` | `surface-container-high` `#e2e7ff` |
| 强调表面 | `surface-container-highest` `#31353f` | `surface-container-highest` `#dae2fd` |
| 主前景/焦点 | `primary` `#4cd7f6` | `primary` `#4648d4` |
| 填充型主操作 | `primary-container` `#06b6d4` | `primary-container` `#6063ee` |
| AI / 生成辅助色 | `secondary` `#c0c1ff` | `secondary` `#4b41e1` |
| 就绪/完成辅助色 | `tertiary` `#4edea3` | `tertiary` `#4651b9` |
| 正文 | `on-surface` `#dfe2ef` | `on-surface` `#131b2e` |
| 次要正文 | `on-surface-variant` `#bcc9cd` | `on-surface-variant` `#464554` |
| 错误 | `error` `#ffb4ab` | `error` `#ef4444` |

`primary` 适合焦点环、文字图标和细边界，`primary-container` 适合填充按钮。不得把一个十六进制颜色直接散落在组件中；组件只消费语义 token。AI、成功、警告、错误也必须使用独立语义角色，不能把所有状态都染成主色。

主题切换不得改变：

- 字体家族、字号、字重和行高；
- 间距、圆角、边框宽度和控件高度；
- 面板位置、断点、焦点顺序和键盘行为；
- 图片色彩、画布背景设置和导出结果。

普通文本对比度至少 4.5:1；大文字、必要图标、焦点边界和关键控件边界至少 3:1。半透明表面必须分别在浅色桌面、深色桌面、复杂壁纸和纯色降级背景上验证，不能只在 Figma 的固定背景上测量。

## 5. 字体与排版

主题不得拥有不同字体系统。统一采用：

- 标题和面板标题：`Geist, "PingFang SC", "Microsoft YaHei UI", "Noto Sans CJK SC", sans-serif`。
- 正文和控件：`Inter, "PingFang SC", "Microsoft YaHei UI", "Noto Sans CJK SC", sans-serif`。
- 尺寸、坐标、版本、哈希和运行指标：`"JetBrains Mono", "SFMono-Regular", Consolas, monospace`。

Figma 数据中的 WenQuanYi Zen Hei、Liberation Serif 及导出时出现的缺字，不视为产品字体定义。实施前必须确认字体许可证、安装/内嵌方式、包体积和 macOS/Windows 的中文回退指标；字体缺失不能导致按钮高度或网格明显跳动。

统一字阶：

| 角色 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| Display | 24 / 32px | 600 | 页面或空状态主标题，少量使用 |
| Heading | 16 / 22px | 600 | 页面分区、主要面板标题 |
| Body | 13 / 18px | 400 | 默认正文和控件 |
| Body Small | 12 / 16px | 400 | 次级说明、紧凑列表 |
| Label | 12 / 16px | 500 | 字段、按钮、标签 |
| Caption | 11 / 15px | 500 | 状态与元数据 |
| Mono | 11 / 14px | 500 | 参数、路径摘要和运行数据 |

字重不超过 600。数值默认使用 tabular figures，避免进度、尺寸和显存数据更新时横向抖动。全大写仅用于 10–11px 的短分区标识，不用于中文正文或长操作文案。

## 6. 空间、密度与响应式

所有主题共用 4px 基础网格。常用间距限定为 4、8、12、16、24px；6px 只允许作为图标或光学校正，不作为页面主网格。

推荐基础尺寸：

| 区域 / 控件 | 基线 |
| --- | --- |
| 自定义窗口栏 | 40px |
| 全局或画布工具栏 | 40–44px |
| 面板标题栏 | 36px |
| 紧凑输入与列表行 | 28px |
| 标准按钮与图标命中区 | 32px |
| 左侧导航 / 素材栏 | 280px |
| 右侧检查器 | 320px |
| 普通右抽屉 | 360px；复杂详情可到 448px |
| Figma 评审基准宽度 | 1280px |
| 首版建议最小窗口 | 1024 × 720px，需真机验证后锁定 |

响应式行为：

- `>=1280px`：允许左侧导航、主内容和右侧检查器同时常驻。
- `1024–1279px`：右侧检查器优先转为抽屉，左侧导航可收为图标栏；核心画布和主提交操作保持可见。
- `<1024px`：首版不承诺完整桌面编辑体验；窗口最小尺寸需阻止进入不可用布局。未来移动端另行设计，不能复用压扁的桌面工作台。

使用 Grid/Flex 的 `minmax(0, 1fr)`、`min-width: 0` 和明确的可收缩区域。不得依靠缩小字号或让按钮换行解决空间不足。滚动区域必须归属于清楚的面板，不能让整个工作台因一个长列表产生双重滚动。

## 7. 无标题栏、透明与毛玻璃

视觉目标是“整体具有透明材质感”，不是把每个内容区域都变成低对比度玻璃，也不是强制 Electron 使用字面意义上的全透明窗口。

### 7.1 Electron 窗口策略

- 去掉可见的系统标题栏，但保留原生窗口控制按钮。
- macOS 优先使用隐藏标题栏和原生 `vibrancy`，保留左上角交通灯。
- Windows 优先使用隐藏标题栏、Window Controls Overlay 和 `backgroundMaterial` 的 Mica/Acrylic 能力。
- 不把 `transparent: true` 作为主窗口默认方案。Electron 官方说明透明窗口可能不可调整尺寸，并限制 Windows 的系统最大化行为。
- 原生材质不可用、性能不达标或用户启用减少透明效果时，降级到对应主题的实色表面。
- CSS `backdrop-filter` 只负责 Web 内容内部的层级，不得把它当成模糊窗口下方其他应用的跨平台实现。

### 7.2 窗口交互

- 自定义窗口栏中的空白区域设为可拖动；按钮、输入框、菜单和可选择文字必须设为不可拖动。
- macOS 交通灯与 Windows 控制按钮拥有不可覆盖的安全区；语言、缩放和最大化后仍保持。
- 可拖动区域禁用意外文本选择，不挂载应用自定义右键菜单。
- 分别验证拖动、双击最大化、系统贴靠、全屏、恢复、跨显示器和高 DPI。

### 7.3 材质分配

- 窗口栏、全局导航、菜单、抽屉和浮动工具岛可以使用毛玻璃。
- 画布、长文本、表单主体和对比视图使用高不透明度表面，保证颜色判断与阅读。
- 毛玻璃不做持续动画；切换只动画 `opacity` 和 `transform`，避免每帧改变模糊半径。
- 内容与壁纸混合后仍必须满足对比度；必要时增加主题 tint 或实色遮罩。

## 8. 导航、面板、覆盖层与抽屉

Figma 的稳定骨架是“窗口栏 + 全局工具栏 + 左侧导航/素材 + 主工作区 + 按需右侧检查器”。P07、P09、P14、P15 等工作台次级能力可以按上下文进入面板或抽屉。

- 宽屏中的高频检查器可停靠；窗口缩窄时转为右侧抽屉，不挤压画布到不可用宽度。
- 普通工作台抽屉优先非模态，不遮罩主画布，允许用户查看画布并调整参数。
- 删除、清空、覆盖、放弃草稿等需要明确决定的流程使用模态 Dialog/Alert Dialog。
- 同时最多展开一个主要抽屉；抽屉内部的轻量选择使用 Popover，不再嵌套第二个主要抽屉。
- 普通抽屉宽 360px，复杂历史或详情允许 448px；窄窗口使用 `min(448px, 90vw)`。
- 模态打开时管理焦点，关闭后返回触发控件；非模态检查器不能无故抢走画布键盘焦点。
- `Escape` 只关闭可安全取消的最上层浮层；有未保存输入时先保留草稿或明确确认。

## 9. 组件技术基线

优先采用成熟组件，不自研通用 Button、Dialog、Tooltip、Popover、Tabs、Select 或焦点管理系统。推荐组合：

| 层 | 推荐 | 责任 |
| --- | --- | --- |
| 组件源码 | shadcn/ui 的 Radix 版本 | Button、Sheet、Dialog、Tooltip、Popover、Dropdown、Tabs、表单等项目内组件 |
| 无障碍原语 | Radix UI Primitives | WAI-ARIA 行为、键盘导航、焦点管理、Portal 和浮层状态 |
| 样式 | Tailwind CSS + CSS variables | 主题 token、密度、状态和响应式 |
| 图标 | Lucide React | 统一线性图标；缺失图标再评估，不混用多套图标风格 |
| 面板调整 | 成熟 resizable-panels 候选 | 只有 P06 验证确需用户调整面板后才采用 |

shadcn/ui 生成到仓库的组件也必须符合本项目编码规则：所有项目内函数和 React 组件使用箭头函数。不得因上游模板使用函数声明而绕过规则；`node_modules` 内第三方实现不属于本项目源码。

采用前仍需完成准确版本、许可证、维护状态、Electron/Chromium 兼容、键盘行为和打包体积核验。当前推荐不等于这些采用门槛已通过。

默认不引入通用动画框架。若后续出现 CSS 无法清楚表达的共享布局过渡，再单独研究并按模块采用，不能为按钮 hover 提前增加依赖。

## 10. 按钮、图标和 Tooltip

中文可见文字按钮的动作短语不得超过 4 个汉字，例如“新建项目”应缩为“新建”，“通过对话创建”可写为“对话起稿”。对象和上下文由页面标题、分组或 Tooltip 补充，不把完整说明塞进按钮。

英文不执行“四字符”限制，但必须使用短动作词并通过最小窗口宽度测试。译文无法在工具栏预算内单行显示时，按顺序处理：缩短译文 → 移入溢出菜单 → 改为语义明确的图标按钮并提供 Tooltip 与可访问名称。禁止缩小到不可读字号或自动换成两行。

按钮规则：

- 文字按钮、图标按钮、标签和分段控件统一 `white-space: nowrap`。
- 图标按钮必须有 `aria-label`；Tooltip 只补充说明，不能成为关键操作名称或危险后果的唯一载体。
- 主提交、危险操作和不可逆操作保留可见文字；高频、可逆且含义稳定的工具可使用图标。
- 图标视觉尺寸通常 14–18px，命中区至少 28px，标准为 32px。
- 禁用状态说明原因；需要解释时在相邻区域或可访问描述中给出，不只依赖悬停。
- Hover、active、focus-visible 和 disabled 状态必须分别设计。焦点环不能被 `overflow: hidden` 裁掉。

Tooltip 默认延迟约 400–600ms，键盘聚焦也可触发。Tooltip 内容保持短句；需要操作或长说明时改用 Popover、Drawer 或帮助区域。

## 11. 中英文与防异常换行

所有界面文案从本地化资源读取，组件不硬编码中文或英文。实施与验收至少覆盖 `zh-CN` 和 `en`。

- 顶栏、工具栏、按钮、标签、状态徽标、分段控件和单行列表标题禁止意外换行。
- 文本所在的可收缩 Flex/Grid 子项设置 `min-width: 0`；溢出使用省略号，并提供完整内容的可访问查看方式。
- 项目名、设计师名和素材名可省略；关键动作名称、错误状态和当前保存状态不得省略到无法理解。
- 多个标签空间不足时折叠为“+N”或溢出菜单，不把每个标签压成两行。
- 路径、哈希和模型标识使用中间或尾部省略；完整值在详情区提供。只有专门的路径/代码区域允许按安全分隔点换行。
- 正文、对话和说明允许自然换行；禁止对普通中文使用 `word-break: break-all`。
- 测试必须使用真实长英文、中文、混排、数字、路径和缺字样本，不能只用占位短词。

## 12. 动效与反馈

动效强调状态变化和空间关系，不作为装饰：

| 类型 | 建议时长 |
| --- | --- |
| Hover / 按压 | 80–120ms |
| Tooltip / Menu / Popover | 120–160ms |
| 抽屉与检查器 | 180–220ms |
| 页面或大型面板切换 | 不超过 240ms |

统一使用快速、克制的 ease-out；关闭可使用更短的 ease-in。禁止弹跳式页面进入、持续缩放、无意义视差和抢夺注意力的装饰循环。

生成或处理中使用真实进度；没有数值时显示阶段状态。活动指示可以轻微脉冲，但不得造成内容位移。结果到达时不抢走当前输入焦点，也不自动切换画布文档。

支持 `prefers-reduced-motion` 或应用内等效设置。减少动态时取消位移、缩放、视差和循环脉冲，只保留必要的即时状态切换或极短淡入。

## 13. 可访问性

- 非画布界面完整支持键盘导航、可见焦点和读屏语义。
- 工具栏使用符合预期的方向键或 Tab 行为；不能创造与系统快捷键冲突的隐藏规则。
- 图标按钮有可访问名称；输入有可见标签；错误与字段建立程序化关联。
- Modal、Alert Dialog、Sheet、Popover 和 Tooltip 使用成熟组件的焦点与键盘模型，不自行模拟。
- 状态不能只靠颜色；使用图标、文字或形状共同表达。
- 画布的图层列表和属性编辑提供键盘可达替代；拖拽不是唯一操作方式。
- 系统或应用启用减少透明效果时使用实色表面，信息层级不消失。
- UI 缩放后核心操作不得被固定栏遮住，也不得因 `overflow: hidden` 变成不可访问。

## 14. 实现前测试与验收矩阵

UI 外壳实现前先写自动化用例和人工 checklist，观察失败后再实现。最低矩阵：

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| UI01 | 只解析 Figma 允许列表 | 非 P 页面不进入快照、token 或实现任务 |
| UI02 | 深色/浅色/跟随系统 | 只改变 token 和材质，不改变布局、焦点、画布数据 |
| UI03 | macOS/Windows 无标题栏 | 控制按钮、拖动、双击、贴靠、最大化、全屏、恢复正常 |
| UI04 | 毛玻璃及实色降级 | 原生材质和降级均可读；画布颜色不受桌面背景污染 |
| UI05 | 1280px 与 1024px 布局 | 检查器按规则停靠/抽屉化；核心操作不被挤出或换行 |
| UI06 | 中文/英文与长内容 | 按钮、标签、状态单行；长名称可恢复完整信息 |
| UI07 | 键盘与读屏 | 浮层焦点进入/返回正确；图标按钮有名称；无焦点陷阱 |
| UI08 | 减少动态/减少透明 | 无循环或大位移动画；实色降级保持层级和对比度 |
| UI09 | UI 缩放 100/125/150% | 无异常换行、遮挡、不可点击区域和窗口控制重叠 |
| UI10 | 画布与玻璃性能 | 真 Electron 中输入响应、GPU/内存和滚动无不可接受退化 |

Figma 或浏览器截图只能作为视觉比对，不能替代 Electron 真窗口测试。macOS 通过不能推断 Windows 通过；透明材质、标题栏和窗口管理必须分别留证据。以后改动已验证的窗口外壳、主题、字体、基础组件、断点或浮层行为，必须登记影响并重新执行相关 UI 编号。

## 15. 明确不做

- 不从当前 Figma 文件的非 DesignHub 页面扩展功能或视觉语言。
- 不为明亮主题建立另一套 DOM、组件树或页面布局。
- 不自研通用组件库、焦点系统或动画引擎。
- 不为了字面“透明窗口”牺牲调整尺寸、最大化、贴靠和跨平台稳定性。
- 不把全部内容都做成毛玻璃；画布、正文和关键表单优先可读性。
- 不在本规范中增加移动端编辑器、协作、插件市场或未在应用说明书确认的能力。
