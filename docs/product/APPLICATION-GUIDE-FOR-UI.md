# DesignHub 应用说明书 · UI 设计交接版

日期：2026-09-08；最近更新：2026-09-15。范围：macOS / Windows 桌面端首版。产品名沿用当前项目目录名 DesignHub，作为工作名称使用。

本文供 UI 设计师、交互设计师和产品开发共同阅读。它描述应用的业务概念、信息结构、完整操作流程、页面内容和状态要求。已经确认的视觉与交互基线见 [UI 基础规范](UI-FOUNDATIONS.md)；本文不重复提供视觉稿或 token。

产品功能来自已确认的 Q1–Q65 产品与交付边界；Q66 将这些内容冻结为 V1 实施基线。“建议交互”是为使流程完整而补充的设计建议，可在不改变业务规则的前提下调整。首版全部功能均在本说明书内，开发按阶段交付，不代表后面的模块自动退出首版范围。

## 1. 产品定位与用户

DesignHub 是用于平面营销物料设计与图像处理的本地优先工作 Agent。用户通过不同的 AI 设计师表达创作方向，在同一项目里完成出图、对话修改、直接工具处理、画布排版、版本比较和交付。

首批用户是独立设计师、品牌或市场人员以及小型创意团队中的个人使用者。首版每份工作区同一时刻只允许一个写入者，团队通过文件包手动交接。不需要平台注册登录，不能把欢迎页设计为登录门槛。

核心价值是将“理解需求—形成风格—生成素材—可控修改—形成系列物料—交付及追溯”保存在同一工作环境中。设计师档案提供持续的视觉方向，画布保留用户对文字与布局的控制，历史让用户能够回退和比较。

典型情境：

| 用户目标 | 起点 | 完成的可见结果 |
| --- | --- | --- |
| 制作春季活动海报 | 一句话、指定文案和品牌 Logo | 多个候选方向、可编辑标题、明确定稿和导出文件 |
| 保持某品牌长期风格 | 品牌包、授权参考作品 | 可复用的设计师档案与项目品牌快照 |
| 电商产品换背景 | 一张原始产品图 | 保留主体的新版本，并能比较处理前后 |
| 请另一设计师继续修改 | 已有作品及历史 | 在同一时间线完成交接，历史贡献保留 |
| 同活动制作横版与方图 | 一张已选海报 | 多份有关联、各有尺寸与定稿状态的设计文档 |
| 转移到另一台电脑 | 工作区目录或项目包 | 原图、作品、历史和署名可继续使用，模型连接重新配置 |

## 2. 首版边界

首版支持社媒图、数字海报、电商图等营销物料；提供普通 PDF 和高分辨率 sRGB 图像交付，包含出血与安全区辅助。它不承诺专业 CMYK / ICC / PDF/X 印前工作流。

原始图像及生成图是栅格素材。用户可叠加编辑文字、图形、遮罩与布局，但不能承诺自动把 AI 图像拆成语义正确的完整源图层。设计图中由模型画出的字，与画布中的可编辑文本必须能够区分。

后续考虑：移动伴侣、显式同步、托管推理计费、调色与批量处理、专业印前。首版不提供完整手机编辑器、实时多人协同、市场或社区、第三方脚本插件、模型权重安装器、原生 Figma / AI 文件编辑。

## 3. 必须统一使用的概念

| 名称 | 对用户的含义 | UI 必须能区分的关系 |
| --- | --- | --- |
| 工作区 | 用户选择的本地目录及其长期创作内容 | 可有多个工作区；当前工作区必须明确 |
| 设计项目 | 一项活动或设计工作，拥有独立文件夹 | 一个工作区里有多个项目 |
| 设计简报 | 项目的目标、文案、尺寸、品牌、设计师和参考材料 | 创建时保留初始快照；后续修改不能抹去初始意图 |
| 设计文档 | 项目内的一份独立物料 | 一张海报与一张横幅是不同文档 |
| 画布 | 当前文档的内容编辑表面 | 画布缩放不是导出尺寸变化 |
| 修订版 | 一次有意义操作后保存的不可变状态 | 新版本不覆盖旧版本 |
| 变体 | 从某个版本出发的候选方向 | 多个变体不是同时被定稿的同一状态 |
| 定稿 | 用户选定的某一个修订版 | 最新版本未必是定稿 |
| 设计师档案 | 有署名、风格、规则和参考的 AI 创作身份 | 不代表真实员工、团队成员或真人在线状态 |
| 设计师版本 | 某次发布后的固定档案 | 更新设计师库不会改写旧项目 |
| 贡献记录 | 具体设计师版本在作品版本中的参与记录 | 当前活跃设计师不等于全部署名者 |
| 本机操作者档案 | 当前设备上用于标注手工编辑和直接工具操作的可选显示身份 | 不是账号、权限、工作区所有权或法律作者认证；历史保存操作发生时的名称快照 |
| 品牌包 | Logo、字体、色板、文案等品牌要求 | 品牌要求与设计师偏好分开显示 |
| 项目时间线 | 消息、交接、操作与结果的统一记录 | 按设计师过滤只是视图筛选，不拆散项目历史 |
| 模型任务 | 已提交或待执行的一项计算工作 | 与设计项目区分，不把二者都简称“任务” |

对话中的“设计师”默认指 AI 档案。署名是应用中的创作溯源，不能暗示真人签署或法律上的作者认证。

## 4. 信息架构与页面清单

以下为逻辑目的地，不强制映射成固定侧栏或独立整页。主工作台应能访问项目文档、对话、图层、工具、历史和交付；UI 设计师决定常驻、折叠、标签页与检查器的组合方式。

## 5. P01：初次使用、打开与切换工作区

初次使用必须允许跳过模型连接，直接建立工作区、导入图像和手动编辑。主入口是“创建工作区”和“打开已有工作区”；已有使用记录时展示名称、本地位置、最近打开时间和可访问状态。

创建字段：工作区名称、本地根目录、可选品牌上下文、可选默认设计师。路径由系统目录选择器提供；取消目录选择返回原表单。目录不可写、重名、存在不兼容内容时说明问题并保留输入。不能误将用户普通文件夹中的内容当成可覆盖缓存。

打开已有工作区检查格式、访问权限和占用状态：

| 状态 | 显示内容 | 可执行操作 |
| --- | --- | --- |
| 正常 | 工作区名称和位置 | 打开 |
| 文件夹已移动或磁盘未连接 | 原位置及原因 | 重新定位、重试、移除最近记录 |
| 已由另一个实例使用 | 只读原因 | 只读查看或取消；不强制抢占 |
| 较旧格式 | 升级说明与备份位置 | 在完成备份后升级，或取消 |
| 较新格式 | 兼容只读提示 | 查看可理解的预览；升级应用；禁止写入 |
| 损坏或内容不全 | 可读范围与失败项 | 恢复备份、查看诊断、重新定位 |

移除最近记录不会删除磁盘工作区。工作区切换保留已保存作品和任务来源；离开有未完成操作的画布时展示真实保存状态。

## 6. P02–P03：手动项目创建

### 6.1 工作区首页

提供项目名称、封面缩略图、简要目标、文档数量、贡献设计师、最近修改、活跃/归档状态。无项目时呈现“新建项目”，并支持导入项目包。不要把生成按钮作为唯一入口。

列表筛选保留在导航返回时；长项目名可完整查看。封面选择、列表/网格表现属于建议交互，不新增业务状态。

### 6.2 手动新建

| 字段 | 要求 | 默认或缺省行为 |
| --- | --- | --- |
| 项目名称 | 建议必填，创建时可提供可修改的建议名 | 与安全文件夹名称分离；同名提示但不覆盖 |
| 所属工作区 / 项目位置 | 明确可见 | 当前工作区下独立项目文件夹 |
| 设计目标 / 面向人群 | 可选 | 留空不阻止手动建立空白项目 |
| 初始文档类型及尺寸 | 建立文档时确定 | 常用预设或自定义；允许先创建无文档项目 |
| 文案 | 可选多行文本 | 保留原始文字，避免模型自行改动固定文案 |
| 设计师 | 使用当前默认，可更换 | 项目保存具体档案版本 |
| 品牌包 | 可选 | 无品牌包也可创作；选中后说明快照语义 |
| 参考材料 | 可选多项 | 显示用途与选中项；导入失败不清空其他字段 |

确认动作是“创建项目”。只有此时生成正式项目文件夹。创建失败留在草稿，可修改或重试；连续点击只能创建一次。空白画布不依赖云模型连接。

## 7. P05：项目概览与多文档

项目概览展示名称、设计简报、当前品牌快照、当前活跃设计师、文档列表、素材入口和时间线。项目状态仅有活跃与归档；定稿属于文档修订版，不给项目强加审核流。

每份文档显示名称、尺寸/方向、缩略图、最近修订版、定稿标记、贡献设计师。用户可新建、重命名、复制、打开、创建关联尺寸稿、移入废纸篓。复制来源保留可追溯关系；复制项目会形成新项目身份，不冒充原项目的后续历史。

关联尺寸稿例如“主海报 → 方图 1080×1080”：展示来源文档与来源版本，新稿单独命名、编辑和定稿。尺寸转换后的裁切、超边和文本溢出需用户可见；不得把自动适配描述为无损。

品牌包或设计师有新版时提示可主动更新。继续使用旧版本不是错误。更换项目上下文只影响后续工作，历史版本继续显示原上下文。

## 8. P06：设计工作台

工作台必须提供以下信息和能力，具体摆放由 UI 设计师决定：

| 区域职责 | 内容 / 操作 | 重要区分 |
| --- | --- | --- |
| 定位与保存状态 | 工作区、项目、文档、当前分支、保存中/已保存/失败/只读 | 保存到本地与云端生成是不同状态 |
| 画布视口 | 缩放、平移、适合窗口、实际像素、背景透明棋盘 | 视口缩放不修改像素尺寸 |
| 内容选择 | 图层命中、多选、边界、锁定、显示隐藏 | 选中图层与选中像素区域不同 |
| 图层管理 | 顺序、命名、锁定、显示、复制、删除 | 原始图像不因图层删除被永久销毁 |
| 属性编辑 | 位置、尺寸、旋转、不透明度、文本及形状属性 | 多选不一致值需表现混合状态 |
| 创作面板 | 对话、当前设计师、附加参考、生成动作 | 指明编辑对象或整个文档 |
| 历史与比较 | 修订版、候选、定稿 | 旧版本浏览不等于回退覆盖 |
| 工具检查器 | 目标、选区、参数、提供方、执行及预览 | 有成本调用与纯本地变换分开提示 |
| 输出 | 导出、尺寸、安全区、字体检查 | 当前预览不一定是定稿版本 |

### 8.1 可编辑能力

首版图层类型为图像、文本、基础形状；支持基本顺序与变换，不加入完整矢量钢笔系统或任意插件。文本层支持内容、系统字体、字号、字重、对齐、行距、颜色；缺字、缺字体和溢出要能定位到对象。图层操作应可通过属性输入完成，不能完全依赖拖拽。

裁切、遮罩和选区必须分开：裁切改变可见范围，遮罩控制透明或显示区域，选区限定一次处理目标。用户需能预览、清除或取消临时选区；退出工具时说明是否保留选区。

### 8.2 保存、撤销和历史

建议交互：一次拖拽松开、一次文本编辑提交、一次参数应用形成一个有意义的编辑批次；鼠标每移动一像素不生成一个历史卡片。连续编辑的自动保存与批次合并由实现验证，但必须保证用户可恢复最近完成的编辑。

撤销/重做发生在当前编辑上下文；已保存的历史不删除。查看旧版本后选择“从此版本继续”会创建新分支。历史版本只读浏览时，明显显示版本身份与“继续编辑”动作，避免用户误以为正在编辑最新作品。

保存失败时留存编辑状态并提供重试或恢复保存途径，不能显示“已保存”。原图加载失败时画布保留占位、尺寸和对象关系，用户可重新定位或恢复素材。

### 8.3 字体与颜色

用户使用本机字体，品牌包记载字体需求。缺少字体不得静默永久替换；预览替代字体必须标识，与用户确认替换区别开。项目包和交付包默认不包含字体文件。常规 PDF 的文字外观处理交由格式验证确定，可栅格化相关文字以保证外观，但应明确其文字不可选择或编辑。

画布与图像导出基于 sRGB。出血和安全区是辅助，不代表通过专业印前验证。毫米尺寸与像素、分辨率之间的关系在设置中可见，不能将高 DPI 标签当作增加图像细节。

## 9. P07：对话、切换设计师与贡献

### 9.1 消息构成

用户消息包含文字、显式附加的图像/版本/选区，设计师消息标明档案名称与版本。工具运行显示结构化任务卡；结果显示候选及后续动作；错误提供原因和恢复入口。所有消息在统一项目时间线中保留。

默认上下文包含项目简报、当前文档、明确附加素材、品牌快照、活跃设计师档案。还应让用户能看到本次使用哪些已有对话或交接摘要。不能自动引用其他项目；跨项目材料必须显式附加，来源可查看。

对话支持流式输出、停止输出、发送失败后的保留与重试。停止文本流不应伪装为已取消远端图像计算。局部修改必须展示目标文档/图层/区域，指令目标不明确时先询问。

### 9.2 直接生成与候选

清晰创作指令默认生成 2–4 个候选，数量在执行前可见并可调整。可先以 2 个为默认交互值；具体数量受已选模型的真实能力影响，不能静默少给并声称全部完成。含糊需求先补充信息。失败候选与成功候选分别展示，成功结果保留。

候选操作：放大查看、加入比较、从此继续、设为定稿、查看生成记录。不自动将全部候选塞进当前画布，也不把新结果盖在用户正在编辑的内容上。

### 9.3 切换设计师

用户在项目内选择另一个已发布设计师及具体版本。显示简短交接摘要，涵盖目标、已选方向、固定文案、保留元素和当前未完成事项。切换记录进入时间线；已有对话保留。

进行中的任务继续使用提交时的设计师快照；切换只影响后续请求。模型配置不支持新档案偏好时提示选择连接，不能默换提供方。

多设计师可以先后参与同一作品，也可以分别形成候选。首版“多设计师”不隐含同时运行多个自主代理或自动评审委员会。

### 9.4 署名与历史

作品详情展示贡献设计师、档案版本、角色和对应修订版；当前版本沿用的祖先贡献可追溯。仅切换到某设计师、不产生贡献，不自动新增署名。直接工具处理记录工具和本机操作者档案在执行时的名称快照，不能虚构当前设计师参与。项目移到另一台设备后保留旧操作者记录，新操作使用当前设备的操作者档案。

默认不把名字烧录进图片。导出显示是否附带署名元数据；格式无法可靠容纳时在随附清单中保留，并说明社交平台可能剥离元数据。普通图像仍可独立使用。

## 10. P08：素材库与导入

首版导入支持文件选择、拖放和剪贴板：PNG、JPEG、WebP、HEIC、SVG、常见动图首帧；PDF、PSD 仅扁平化导入。PDF 建议提供页选择，PSD 若无可解码合成预览则说明原因，不假装读到全部图层。

导入列表逐项显示文件名、类型、尺寸、状态和错误。动图明确标注“仅首帧”；扁平化源文件标注“图层不可编辑”；SVG 只接受安全图形内容，不执行脚本或隐式网络资源。拒绝不支持格式时保留其他成功文件。

默认复制完整原始文件到工作区，显示其受管状态；工作区内内容去重，不依赖原始外部路径。高级外部引用需标明路径、缺失风险和“转为受管副本”操作。字体等许可文件的携带规则单独处理。

素材详情：预览、文件名、类型、尺寸、来源、用途、关联项目/文档、授权备注、复制到工作区状态。项目内可“放入画布”“作为参考”“替换选中图像”；三种操作不能混为一个隐式默认动作。

删除仍被历史引用的素材时显示引用影响，不能永久破坏历史。废纸篓恢复后恢复其可用性；清空时仍受引用保护。缩略图加载不全与原始文件损坏需区分。

## 11. P09：修订版、比较与定稿

历史条目显示时间、操作概述、贡献设计师、来源版本和结果缩略图。可按设计师或操作类型过滤，但完整父子关系仍可访问。

比较最少支持两张候选并排、查看相同缩放及版本信息；处理前后比较可用滑块或切换，具体形式交 UI 决定。比较状态不改变作品。

设为定稿是用户明确行为，显示文档名与版本。已有定稿时改选可更新定稿指向，同时保留事件记录。继续编辑后原定稿依然有效，提示“有更新版本尚未定稿”。从老版本继续自动分支，禁止覆盖旧分支。

当 AI 运行期间用户继续编辑，迟到结果保存在其原始版本的候选分支；显示“基于较早版本生成”。用户决定从结果继续或另行应用，系统不自动合并复杂画布。

## 12. P10–P12：设计师管理

### 12.1 库与默认值

库里区分用户已发布、草稿、已归档。列表内容包括名称、风格摘要、示例、当前发布版本和默认范围。空工作区显示明确空状态，不注入应用拥有的档案。不能使用真人在线、忙碌或团队权限状态代替 AI 档案状态。

默认值顺序：项目显式选择 > 工作区默认 > 全局默认。引用不可用时显示未设置状态，用户可从作品集分析创建或导入新的档案；系统不会伪造或注入默认设计师。

### 12.2 创建路径

新设计师仅可通过作品集分析创建：选择本机图片集/压缩包、图片直链或公开页面 → 确认使用权 → 预览并选择图片 → 分析 → 审核草稿。现有档案可编辑、设为默认、用于新建项目或归档，但不能派生为新设计师；新档案始终从这条作品集分析链路开始。公开页面不登录、不带 Cookie、不全站爬取、不持续同步；无法解析时提供手动导入，不要求在应用里登录第三方站点。

作品集图片逐项可移除，展示选中数量与分析范围。损坏文件、过大资源、页面无图、部分抓取失败均可恢复；不因一张坏图丢失整个草稿。

默认只保留来源、授权声明及提炼后的特征。原始参考资料仅在用户选择“归档参考资料”时永久保留。分析临时文件在完成/放弃后清理；不归档时需说明未来不能仅凭链接保证原始参考可再次取回。

### 12.3 草稿字段

| 分组 | 内容 |
| --- | --- |
| 身份 | 原创名称、署名、说明、示例缩略图 |
| 视觉特征 | 色彩倾向、构图、字体倾向、材质、元素、留白与信息密度 |
| 创作规则 | 优先策略、文案处理、保留要求、禁用元素 |
| 来源 | 选中的参考作品、来源与授权声明、是否归档 |
| 能力偏好 | 对话/图像模型与工具偏好，可留空使用可用默认 |
| 验证 | 可选样张与用户评价；样张生成展示模型和费用 |

分析必须允许不确定和风格混合，不伪造可量化的风格准确率。用户可修改提炼结果。确认“发布设计师”后进入已发布库；关闭编辑保留草稿，不默认发布。

### 12.4 更新与删除

修改已发布内容生成新草稿，发布后产生新版本；旧项目不自动升级。详情需显示当前库版本和项目正在使用的版本不同。

被项目引用的设计师删除动作实际为归档，署名和快照保留。完全未引用的档案可先移至可恢复废纸篓，永久删除需清空。重新启用归档档案可作为恢复操作，不改写旧版本。

## 13. P13：品牌包与创作约束

工作区可有可选品牌包；包含名称、Logo、色板、字体要求、语气、固定文案、尺寸预设、许可资料。创建项目保存快照；项目覆盖要显示哪些字段与品牌原件不同。

约束优先级固定为：本次用户明确指令 > 文档/项目显式覆盖 > 品牌快照 > 活跃设计师 > 全局默认。明显冲突需提示具体字段和即将采用的要求。例如用户说“Logo 换成白色”，显示当前品牌要求与本次覆盖，不悄悄忽略用户指令，也不新增无穷确认弹窗。

修改品牌库后既有项目继续使用原快照。用户主动应用新版时显示字段差异，历史继续保留旧品牌内容。Logo 或字体缺失时定位问题，不静默拿别的品牌资产替代。

## 14. P14：图像处理工具箱

共通流程为“选目标 → 设参数/区域 → 查看调用范围 → 执行 → 比较结果 → 从结果继续”。纯本地尺寸等操作提供即时预览；需要模型的预览也可能收费，不能伪装成免费本地预览。

| 工具 | 输入与关键控制 | 成功结果 | 必须设计的异常 |
| --- | --- | --- | --- |
| 去除背景 | 目标图像、边缘/保留区域（能力支持时） | 带透明度的新图像版本 | 主体识别不准、半透明边缘损伤、模型不支持 |
| 更换背景 | 目标、背景描述或图、主体保留范围 | 原主体与新背景组合 | 原图首次上传确认、背景图丢失、主体被改动 |
| 对象移除 | 图像和明确选区 | 局部修复版本 | 无选区、选区空/越界、结果瑕疵 |
| 对象添加 / 局部重绘 | 目标、区域、描述和可选参考 | 局部变化版本 | 未指定位置、无所需能力、外部区域意外变化 |
| 扩图 | 原图、目标边界、延伸方向/描述 | 扩展画面版本 | 目标小于原图、极大尺寸、边缘接缝 |
| 智能裁切 | 原图、目标比例/尺寸、焦点 | 裁切预览与新版本 | 重要内容被裁、低分辨率、模型不可用 |
| 放大 / 修复 | 倍率或目标尺寸、可用修复选项 | 更高分辨率或修复版本 | 能力上限、内存不足、过度锐化/伪细节 |
| 尺寸转换 | 宽高、比例约束、重采样规则 | 指定像素尺寸版本 | 零/负值、超限、意外拉伸 |
| 格式转换 / 压缩 | 输出格式、质量、透明底处理 | 新转换产物与记录 | JPEG 无透明度、写入失败、目标覆盖冲突 |

参数仅展示已选工具/模型真正支持的项。不可用工具应说明“需要连接支持此功能的模型”，并保留当前选择。直接工具调用和对话调用写入同一历史；工具失败不生成假的设计版本。

## 15. P15–P16：模型任务与连接

### 15.1 连接设置

用户可以单独配置对话、图像生成和图像编辑能力；同一提供方可以提供多个能力。本地服务由用户自行安装运行，应用负责连接检测和说明，不下载模型权重。

云端连接字段：提供方、连接名称、API Key、安全显示/替换入口、支持能力和可用模型。仅受验证适配器支持的自定义地址可显示；不提供任意脚本执行入口。Key 掩码显示，不进入聊天、项目、备份或导出。

连接检测区分未配置、检测中、可用、凭据无效、网络不可达、能力不支持、服务返回错误。检测失败不清空用户其他配置。新设备导入项目后显示缺失连接，但仍可看图、编辑与导出。

首次连接提供方时说明会接收的数据类型；切换提供方或首次上传原图需要确认。后续任务持续显示提供方与本次上传范围，不对相同已同意范围反复弹窗。缺少凭据时不能偷偷改用另一个付费提供方。

### 15.2 任务状态

| 状态 | 内容 | 操作 |
| --- | --- | --- |
| 排队 | 来源、目标、提供方、候选数、可得的费用估计 | 取消 |
| 处理中 | 当前阶段，真实进度或不确定进度 | 能力允许时取消；继续编辑其他内容 |
| 完成 | 结果、耗时、已知用量、来源版本 | 查看、比较、继续、生成记录 |
| 失败 | 错误原因、是否可能已计费、恢复建议 | 原模型重试、明确选择替代、调整参数 |
| 已取消 | 本地停止状态与远端取消结果 | 查看记录、重新提交 |

中断后若能查到远端任务，恢复查询；无法确定结果时显示“结果未知/需检查”，作为失败或处理中状态的恢复说明，不自动重新提交收费请求。应用关闭后不承诺模型一定取消，窗口关闭与进程退出的行为需区别说明。

取消请求与取消完成分开。提供方不支持取消时，允许停止等待，但告知远端可能继续计算或计费。重试创建新的尝试记录并关联原请求。重新联网不静默上传离线草稿。

### 15.3 费用与生成记录

可获得估价时展示币种、单次/候选数量及估价依据；未知显示“提供方未提供估价”，不能以 0 元代替未知。实际用量与费用仅展示可验证数据。模型能力不匹配和服务失败时由用户选择替代，禁止静默降级。

生成记录保存用户可见最终指令、模型、提供方、参数、参考素材标识、结果、时间。它支持从历史生成新变体，不承诺模型版本变化后位级复现。隐藏内部提示词和机密不进入记录。

## 16. P17：导出、交接与分享

导出先明确文档与版本：当前修订版或定稿。多文档项目可逐份选择交付文档；这里的交付选择不扩大为首版批量图像处理功能。

| 输出 | 参数与内容 | 限制 / 反馈 |
| --- | --- | --- |
| PNG | 尺寸、透明度、sRGB | 原图细节不足时提示，不宣称放大即增加细节 |
| JPEG | 尺寸、质量、背景色 | 不支持透明底，必须给出合成背景预览 |
| WebP | 尺寸、质量、透明度（能力支持时） | 格式兼容说明 |
| 普通 PDF | 页面尺寸、边距/出血辅助、外观预览 | 非 PDF/X；不默认嵌入字体，明确栅格化文字结果 |
| 项目包 | 简报、文档、历史、所需素材、设计师/品牌快照 | 完整可继续编辑；排除密钥和默认不携带字体 |
| 只读交付包 | 选定输出、预览、交付清单、署名 | 不含内部聊天、提示词和不必要源素材 |

用户选择目标目录；“同时归档到项目 exports 目录”默认可选关闭。每次导出记录版本、参数、目标与成功状态。外部文件被用户移动后，记录仍在，但不能假装原路径还有效；提供重新导出。

写入失败、磁盘已满、同名文件已存在要提供具体恢复操作。同名不默默覆盖；建议另存文件名。正在编辑时导出绑定提交时版本，不随画布变化漂移。

项目包导入先校验和预览名称、格式、体积与缺失项，再落地到新项目目录。重名或 ID 冲突不能覆盖现有项目。不同设备字体或模型连接缺失应是可恢复状态，不能阻止其他内容打开。

## 17. P18：分类与检索

提供工作区、品牌包、项目/文档、贡献设计师、物料尺寸、定稿、标签、修改时间筛选；全文检索设计简报和用户可见元数据。设计师过滤按贡献记录匹配，不仅看当前活跃者；归档设计师参与的旧作品仍可找到。

检索结果显示名称、缩略图、命中字段、工作区/项目路径、贡献者和版本信息。无结果时保留条件，提供清除部分筛选；索引重建时区分暂未收录与真实零结果。首版没有视觉相似或云端语义检索。

## 18. P19：归档、删除、恢复与备份

归档项目保留内容并从活跃列表收起，可以恢复。删除项目、文档、素材先移入本地废纸篓，不自动过期。废纸篓展示原位置、删除时间、占用空间和引用限制；支持恢复，清空需明确永久删除范围。

清空一组对象时，只保护仍被本次清空范围之外的项目或历史引用的资源。整体清空一个已删除项目，不应因项目内部自引用而永远无法清空；共享原图若仍被其他项目使用则必须保留。

备份默认不上传云端。用户选择本地或外接磁盘位置，可手动或定期增量备份。展示上次成功时间、目标是否在线、大小、进行中状态、失败原因。目标磁盘未连接时提示跳过或失败，不悄悄改写到另一个目录。

恢复先选择备份、校验并预览。建议恢复到新目录后打开验证，避免覆盖当前工作区。只有真正校验成功才写“恢复成功”。工作区被移动时，通过重新定位恢复入口，不要求重新建立所有项目。

## 19. P20：设置、离线和平台体验

应用设置：简体中文/英文、全局默认设计师、本机操作者档案、模型连接、本地诊断包、最近工作区。工作区设置：路径、工作区默认设计师、品牌包、备份位置及周期。项目覆盖在项目中编辑，不藏到全局设置。

首版只生成本地诊断包，不提供自动网络发送或远程遥测开关。导出前必须预览内容范围并由用户主动选择保存位置；素材、项目结构、路径、提示词、创作内容和密钥全部排除。首版数据保护依赖系统权限和用户磁盘加密，不展示未实现的应用加密开关。

离线仍可浏览、画布编辑、版本管理、本地搜索、导出与备份；已运行本地推理服务可继续用。云任务不能执行，草稿保留；重连后由用户发起，不能显示“稍后自动上传”式承诺。

macOS / Windows 的文件选择、快捷键修饰符、菜单、窗口关闭规则和路径格式需分别考虑。首版中文和英文都要覆盖长文案、系统缩放、输入法组合输入和字体缺失。未来移动端只作为浏览、审阅、评论、分享、导出伴侣，本次不要求手机高保真页面。

应用使用无可见系统标题栏的自定义窗口栏，并保留 macOS / Windows 原生窗口控制区域。透明材质、毛玻璃、窗口拖动区、明暗主题、断点和降级行为统一按 [UI 基础规范](UI-FOUNDATIONS.md)执行；不能为了字面全透明破坏调整尺寸、最大化或贴靠。

## 20. 全局状态与交互约束

每个页面至少设计加载、正常、空、错误、部分失败、只读和操作中状态中适用的组合。模型未连接不等于所有页面禁用；工作区只读与控件不支持必须有不同解释。

| 事件 | 期望反馈 | 可恢复路径 |
| --- | --- | --- |
| 保存期间关闭窗口 | 显示保存结果，失败时保留恢复入口 | 重试、取消关闭或保存恢复副本 |
| 未保存长表单离开 | 草稿保留状态明确 | 返回草稿或明确放弃 |
| 连续点击创建/执行 | 一次动作的进行中状态 | 不创建重复项目/请求 |
| 云请求超时 | 不确定远端状态与可能费用 | 查询状态或用户明确重试 |
| 新结果到达旧文档 | 不抢走当前文档焦点 | 通知并定位结果 |
| 删除仍被引用资产 | 解释影响 | 保留历史所需内容、取消或移除当前引用 |
| 外接盘拔出 | 保存失败与工作区不可用 | 重新连接、恢复保存 |
| 未知新格式 | 只读且有能力限制 | 升级应用、查看缓存预览 |

错误文案使用“发生了什么 + 当前数据状态 + 下一步”，不向普通用户暴露堆栈、数据库字段或内部状态码。任务进度仅用真实数值，无进度信息时用阶段描述。

中文可见文字按钮的动作短语不超过 4 个汉字。英文使用短动作词并在最小窗口宽度验证；空间不足时使用溢出菜单或具有 Tooltip 与可访问名称的图标按钮。按钮、标签、状态徽标和分段控件禁止意外换行，关键与危险操作不能只用图标或悬停说明。

## 21. 可访问性与交互交付标准

首版非画布界面应完整支持键盘操作、可见焦点、读屏语义、缩放与减少动态效果。关键操作不能仅靠颜色、悬停、精确拖拽或图标猜测。输入字段有可见标签；错误关联字段，提交失败可定位；模态打开后管理焦点，关闭后返回触发位置。

普通文本对比度目标至少 4.5:1，较大文字和必要控件边界至少 3:1。桌面工具密度由 UI 设计师权衡，不能机械套用手机 44px 控件占满画布；仍需提供足够命中区域与键盘替代。

建议快捷键覆盖新建、打开、保存、撤销/重做、导出、缩放适配、取消选区和打开搜索。具体组合需避免系统及输入法冲突；在文本输入时 Delete、空格、方向键不应触发画布全局操作。

缩放后的非画布内容不得被固定面板遮住。大列表、较慢缩略图、长对话和图像任务期间保持可交互；复杂画布可渐进增强读屏，但图层列表与属性编辑应提供可访问替代。

## 22. UI 设计交付清单

| 交付项 | 最低内容 |
| --- | --- |
| 信息架构 | P01–P20 目的地关系、工作区/项目/文档作用域与返回行为 |
| 核心用户旅程 | 手动新建项目、作品集创建设计师、生成修改、直接工具、切换设计师、定稿交付、跨设备打开 |
| 页面设计 | 每页职责、字段、主次操作、适用状态、长内容与空内容 |
| 工作台组合 | 对话/图层/属性/工具/历史共存与收起方式、窗口缩窄策略、停靠与抽屉转换 |
| 状态组件 | 任务卡、候选卡、版本卡、署名、模型连接、保存/只读、错误恢复、云端告知 |
| 表单与浮层 | 简报、档案、品牌、连接、导出、删除/恢复、模型替代 |
| 平台与语言 | macOS/Windows 无标题栏与毛玻璃差异、中文/英文样本、长文本、系统缩放、实色降级 |
| 可访问性说明 | 焦点顺序、键盘替代、读屏标签、减少动效、状态语义 |
| 标注 | 每个交互对应页面 ID、操作结果、是否写历史、是否调用模型 |

建议按“全局导航与项目入口 → 工作台与历史 → 设计师与品牌 → 设置和交付 → 异常状态”评审。UI 交付验收以流程能否完成为准，不以页面数量为准。

UI 不要求一次性交付全部 P01–P20。M01 可依据已确认的 UI 基础规范先实现窗口外壳和实际使用的基础组件；后续每个模块在开始其视觉实现前，必须取得 UI 设计师对该模块相关页面、适用状态、双语和响应式行为的交付或明确确认。领域逻辑与技术验证可在不猜测视觉方案的前提下先行。

## 23. 供评审使用的贯穿案例

使用虚构品牌“春间市集”：Logo、一张产品原图、固定标题“把春天带回家”、海报 2480×3508 像素、方图 1080×1080。设计师 A 为“纸感排版”，设计师 B 为“清晰商业”。示例尺寸仅是交互样本，不限制用户输入。

验收旅程：创建工作区 → 导入 A 的作品集并完成分析后发布 → 手动新建项目 → 导入原图 → A 生成两个方向 → 选择一个，在画布上添加可编辑标题 → 切换 B 保留主体并调整背景 → 比较前后 → 创建方图关联文档 → 分别定稿 → 导出 PNG 和只读交付包 → 打包项目到另一设备 → 缺少模型连接时仍能浏览编辑导出。

异常变体：第二个候选失败、B 的模型不可用、生成途中用户继续编辑、导出目标盘拔出、新设备缺字体、设计师 A 被归档。UI 设计需能完整说明这六种恢复流程。

## 24. 与实施计划的关系

完整实施安排见[全模块计划](../superpowers/plans/2026-09-08-designhub-v1.md)，技术边界见[架构说明](../superpowers/specs/2026-09-08-designhub-v1-design.md)，视觉与交互约束见 [UI 基础规范](UI-FOUNDATIONS.md)。桌面基础现为 Electron；它不改变上述产品层级和用户流程，但无标题栏、原生毛玻璃和跨平台降级需要由设计与 Electron 窗口实现共同验收。

UI 方案若增加新业务状态、自动付费行为、跨项目读取、协作或新的交付格式，应列为产品变更后再实施。配色、排版和面板视觉设计属于 UI 设计职责，可在这些业务约束内自主探索。

## 25. 高级创建与图像工具当前交互补充

新建项目抽屉的创建方式包含“标准设计”“智能构图”“样机”。智能构图必须先选择核心素材，可选素材和参考素材分别上传；页面明确提示这是本地候选，尚未经过真实模型验证。样机提供手机屏幕、海报画框和包装袋模板，以及模板颜色和源图尺寸校验；模板原件不可修改。

智能构图或样机创建成功后，应用直接打开项目文档和候选画布。候选工具条提供“本地候选/待确认”状态、“确认候选”和“放弃候选”；确认才写入正式修订，放弃返回原始场景。栅格回退候选必须显示“栅格候选/不可编辑”，不能让用户误以为是可分层结构化稿。

本地候选会随项目库持久化。用户关闭应用或离开文档后，下一次打开应回到尚未确认的候选画布；已经确认或放弃的候选不能再次出现。若正式修订已创建但候选审计状态保存失败，界面必须保留候选和重试提示，不能仅显示“已完成”。

项目包交接页面需要表达“源库可离线、目标库独立”的语义：导入后项目拥有新身份，但保留历史修订和素材引用；用户可继续编辑并再次导出。目标文件已存在或导入校验失败时，保留原目标、不显示半成品，并给出可恢复动作。真实 provider 质量、样机透视/遮挡和大包性能不在 UI fixture 验收范围内。
