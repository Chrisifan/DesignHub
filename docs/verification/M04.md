## Task 2: immutable revisions, branching, finalization, and attribution

Task 2 adds an in-memory revision contract that keeps revision payloads immutable, makes retries idempotent by `operationId`, and validates document ownership for parents and final pointers. Designer contributions and the local operator name are copied into each committed revision as snapshots; direct tool commits do not invent a designer contribution.

### Acceptance scenarios

| ID | Scenario | Evidence |
| --- | --- | --- |
| R01 | A late result branches from its original base without changing that base. | `branchRevision` returns a new child and leaves the base object unchanged. |
| R02 | Duplicate completion callbacks do not create a second revision. | Repeating a commit with the same `operationId` returns the original `revisionId`. |
| R03 | Parents and final pointers cannot cross document boundaries. | Commits with a foreign parent and finalization with a foreign revision throw `DOCUMENT_MISMATCH`. |
| R04 | Revision payloads keep immutable asset, scene, contribution, and operator snapshots. | Mutating caller arrays/objects or later designer names does not alter the stored record. |
| R05 | Direct tools do not receive synthetic designer attribution. | A commit with no contributions stores an empty contribution list. |
| R06 | Timeline and comparison views consume stable revision/event contracts. | Components render supplied events and side-by-side revision metadata. |
