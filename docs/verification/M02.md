During the normal path, the project container receives a reserved trash sidecar before its move into workspace-managed `trash/<project-id>` and restore removes the copied sidecar before publishing the active result. An injected stop after sidecar creation can leave that file in the active project; reopening treats the valid active container as authoritative, and a later trash attempt removes the stale sidecar before writing current metadata. The sidecar records the stable project ID, workspace-relative original path and deletion timestamp. Purge receives only a project ID, requires a live reference provider at mutation time, and removes only the managed trash directory; it never receives or deletes draft/source paths.

Automated evidence covers T01 and the M02 storage portions of T02–T07. M04 has not yet supplied ancestor-revision or archived-project reference calculation, so historical/archive counts are intentionally unverified and a purge without a provider is rejected. P01/P02 design delivery remains unavailable, therefore no `TrashView.tsx`, UI listing, or UI cached-reference behavior was implemented. Native Windows behavior, real process termination during filesystem copy/delete, durability across an OS or power loss, and packaged Electron-side trash exercise remain open; no automatic expiry exists.
