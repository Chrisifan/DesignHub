## Task 4: Workspace-backed library and draft persistence

### 2026-09-12 correction and regression record

- Red: UI regression tests exposed that an empty persisted profile list could hide built-ins and that read-only workspaces still exposed mutation controls.
- Green: built-in profiles are merged as an application fallback; read-only mode disables create/edit/derive/default/delete and suppresses writes; editing a published profile creates a new draft identity; referenced profiles are archived instead of deleted.
- Focused regression: `src/app/studio/DesignerLibrary.test.tsx` — 7 tests passed; storage/IPC persistence suites — 6 tests passed.
- Open: injected atomic rename failure cleanup, native keychain behavior, real M06 portfolio analysis, historical project integration, and cross-platform UI remain unverified.

The designer library state is stored in `.designhub/designers.json` inside the active workspace. Renderer code uses the typed desktop bridge (`loadDesignerState` / `saveDesignerState`) and has no browser `localStorage` fallback for designer data. State includes published, built-in, draft and archived profile records, the selected default id, the in-progress create draft and profile edit drafts. Writes are validated and atomically replaced through a same-directory temporary file; read-only workspaces can load but cannot save.
