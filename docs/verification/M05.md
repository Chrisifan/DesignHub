## Task 4: workspace-backed document scene persistence

### Pre-implementation checklist

| ID | Failure prevented | Verification |
| --- | --- | --- |
| P01 | A canvas scene disappears when the workspace is reopened. | A validated scene is saved under the project document directory and reloads after reopening the workspace. |
| P02 | A renderer writes outside the active workspace/project or bypasses the writer lease. | Trusted IPC checks workspace identity; storage rejects invalid document ids, missing projects, read-only workspaces, and symlinked paths. |
| P03 | A crash or partial write leaves a truncated scene file. | Saves use a uniquely named temporary file followed by an atomic rename; malformed scene files load as empty/missing state. |
| P04 | Canvas edits stay example-only when a real workspace document is open. | `CanvasWorkspace` optionally hydrates through the desktop bridge and saves inspector/drag scene changes through the same typed contract. |

### TDD and verification evidence (2026-09-12)

- Red: `pnpm exec vitest run --config vitest.config.ts src/desktop/storage/scene-store.test.ts src/desktop/ipc/scenes.test.ts` failed because the scene-store and IPC modules did not exist.

Document scenes are validated with the finite `DesignScene` schema and stored at `projects/<projectId>/documents/<documentId>.scene.json`. Loading is allowed for read-only workspaces and returns `null` for missing or malformed data; saving requires the active writable workspace lease and performs an atomic replace. The renderer bridge is optional so existing preview/example surfaces remain usable without a desktop workspace.
